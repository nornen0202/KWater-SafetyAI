# 공식 앵커의 Fold 0 내측 보정 재생

기존 공식 기준선 216장과 고정 0.50 앵커 102개를 보존했다. 완전 내측 OOF 확률 750장에서만 정밀도를 산출하고, 저장된 Fold 0 온도·코드/장면 임계값과 기존 정밀도 게이트를 한 번 적용했다. 새 임계값을 탐색하지 않았고 GPU·새 생성·A/B 102개 패널에는 손대지 않았다. [CPU 집계](../results/v2_official_anchored_true_nested_replay.json)

## 후보 변화와 이미 관측한 수용

| 범위 | 요청 | 공식 주석 일치 / 미표기 | 기존에 실제 수용한 일치 / 미표기 |
|---|---:|---:|---:|
| 고정 기준 전체 | 102 | 31 / 71 | 28 / 49 |
| 양쪽 동일 사진·코드 | 74 | 24 / 50 | 22 / 38 |
| 다른 코드로 교체된 기존 요청 | 4 | 1 / 3 | 1 / 2 |
| 교체 없이 사라진 요청 | 24 | 6 / 18 | 5 / 9 |
| 같은 사진의 교체 요청 | 4 | 4 / 0 | 1 / 0 |
| 이전에 요청하지 않은 사진의 요청 | 3 | 0 / 3 | 0 / 0 |

내측 보정은 81개를 골랐다. 동일 사진·코드 74개의 수용 결과는 기존 공식 앵커 원문에서 확인했다. 교체 위험의 **한 건**은 기존 단독 후보 후속 캐시에 있었다. 모델 키, 시스템 프롬프트 SHA, 공통 코드별 사용자 프롬프트, processor 크기, 생성 토큰 상한, 배치 크기, 현재 사진 바이트 SHA 및 후보 코드가 일치했다. 두 캐시가 공유하는 항목의 원문 문자열도 일치했고 현재 엄격 파서가 기록된 수용 판정을 모두 재현했다. 추가로 찾은 한 건은 공식 주석과 일치하며 실제 수용됐다. 나머지 여섯 건은 **공식 주석 일치 3건, 미표기 3건**이며 수용은 확인되지 않았다.

## 전수 가능 범위

| 조건 | Macro F1 | 무위험 오경보 | 중대성 4 완전 미탐 |
|---|---:|---:|---:|
| 기존 고정 정책 실측 | 0.60528 | 17/65 | 12/49 |
| 앵커 캐시만 사용. 미확인 7건의 128개 조합 | 0.59098~0.62459 | 14~15/65 | 12~13/49 |
| 일치하는 후속 캐시 1건 추가. 미확인 6건의 64개 조합 | 0.59413~0.62459 | 14~15/65 | 12/49 |
| 새 제안 81개에서 주석 일치만 수용하는 oracle | 0.68470 | 6/65 | 11/49 |

64개 조합은 남은 수락·거절을 가능한 모든 방식으로 바꾼 계산이다. 실측 분류 성능으로 해석하지 않는다. 최선 오경보 **14/65(21.54%)**가 20%를 넘으므로 남은 여섯 요청의 GPU 실행으로 기준을 통과할 수 없다. 이 경로의 신규 생성은 생략할 수 있다. 34장 제외 민감도의 한 미확인 요청을 전수한 F1은 0.63373~0.66547, 오경보 2/6, 중대 미탐 3건이다. 발표용 정량·공식 정성 점수에 대한 결론은 개발 자료 범위를 벗어난다.

## 관련 실파일 확인

- BF16 v2의 127개 위험 사진에 대해 출력된 185개 위험 항목은 각각 인용 한 건을 포함했다. 블라인드 12장 중 후보의 위험 항목 10개도 각각 한 건을 인용했다. 인용 존재의 집계이며 사진·조치와 지지가 일치하는지는 별도 정성 감사에서 확인했다.
- 현재 하이브리드 패키지는 전체 개발 보정 `full_dev_calibration`과 전 개발 OOF의 코드별 정밀도를 이미 사용한다. 독립보고용 Fold 0 내측 보정은 이번 진단 정책이다. `val_fold=-1`의 훈련 대상 조건인 전체 개발은 966장이다. 로컬에서 확인된 완료 v2는 Fold 0용 750장 학습이다. [패키징 코드](../kwater_lab/package_submission.py)
- 공식 동봉 legacy 8-code 변환 학습 자료는 1,044행이며 현재 Fold 0의 215/216개 사진 ID를 포함한다. 동봉 변환 자료의 포함 집계이며 배포 가중치가 실제로 본 개별 학습 ID의 기록은 아니다.
