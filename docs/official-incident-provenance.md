# 공식 사진을 사고 사례별로 나누기 위한 선행조건

**공식 학습 사진 1,045장의 사고 경계를 검증하려면 사진을 원 사고와 연결할 출처 자료가 필요하다.** 이번 점검에서는 PNG 청크 헤더와 JSONL 최상위 및 `notes`의 필드 이름을 집계했다. 등록 사진 수와 라벨 파일 해시는 기존 전수 감사와 일치했다. 사진 디코딩과 라벨 판독은 0건이다. [기존 감사](../results/train_audit_summary.json) · [재현 집계](../results/official_incident_provenance.json)

| 확인 항목 | 발견 수 |
|---|---:|
| EXIF 청크, EXIF 촬영 시각, 원본 이미지 고유 ID | 각 0장 |
| PNG 텍스트 청크, PNG 수정시각 청크 | 각 0장 |
| ICC 색상 프로파일, 픽셀 밀도 | 각각 34장, 6장 |
| 최상위 또는 `notes`에서 확인된 사고·원보고서 식별 필드 | 0개 |

모든 행에 `sample_id`, `image`, `target`, `notes`가 있었고, `notes`의 필드는 `scene_note`와 `uncertainty`였다. 운영진에게 요청할 가장 직접적인 자료는 **학습 사진 ID ↔ 원 사고관리번호** 대응표다. 원보고서 번호만 제공된다면 한 보고서에 포함된 사고 수, 동일 사고를 다룬 여러 보고서, 사진의 원보고서·사진 순번을 먼저 대조해야 한다. 사진 해시는 정확히 같은 파일을 찾는 용도다. 접두사, 촬영 시각 또는 저작자 일치는 사건 동일성을 확정할 근거가 되지 않는다.

프로젝트 루트에서 `python -m kwater_lab.official_incident_provenance`를 실행하면 집계를 재생성한다. 출력은 필드 이름과 빈도뿐이다.
