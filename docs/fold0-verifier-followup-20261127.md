# Fold0 재판독 후속 실행 기록

Windows 실행기는 먼저 216장 후보를 검사하고 공식 1차 LoRA의 216장 결과와 대응 비교를 저장한다. 이후 같은 정밀도와 배치로 사진당 최대 1개의 전문가 제안을 Qwen으로 재판독한다. 후보 선택은 Fold0 학습 모델만 쓰고, Fold0 라벨을 참조하지 않는 고정 0.5 정책을 사용한다. 첫 판독이 이미 쓴 위험과 3개 상한을 보존한다. 후보 수락은 기존 엄격한 코드별 파서를 통과해야 한다. 공식 비교에 쓴 216장과 기존 정성 검토용 36장은 그대로 유지한다. [Windows 실행기](../tools/run_fold0_vlm_pair.ps1) · [후보 평가기](../kwater_lab/hybrid_pipeline.py)

후속 실행은 대응 집계, 공식 출력, 원 후보 출력, 학습 어댑터, 개발 manifest 해시가 일치하고 원 생성 캐시에 216장이 다 있을 때만 시작한다. 원 후보 JSONL 및 원문 캐시는 읽기 전용으로 사용한다. 재판독의 사진·코드 순서, 이미지 해시, 전문가 가중치, 프롬프트, 평가 코드, 모델 정밀도·생성 설정을 재개 지문에 포함한다. 배치를 마칠 때마다 원문과 판정이 원자적으로 저장된다. 이어서 실행하면 저장된 배치는 재생하고 남은 배치만 수행한다. [재판독 캐시](../kwater_lab/verifier_cache.py)

후속 집계는 제안과 수용 건수, 신규 정답·오답 코드, 무위험 사진에서 새로 생긴 경보 수, 종전과 재판독 후의 중대성 4 미탐, 공식 LoRA 대비 효과를 같은 분모로 기록한다. 이전 후보와 공식 LoRA 각각에 대한 비교는 기존 사건 단위 2,000회 쌍체 재표본화를 사용한다. 시간은 현재 호출의 재판독 구간, 저장 배치가 포함된 누적 생성·모델 로드 구간, 재사용한 후보 수로 구별한다.

요청된 zero-shot은 재판독이 끝난 다음에 실행한다. 재판독용 모델이 메모리에 남아 있다면 PEFT 어댑터를 일시 해제해 기반 가중치를 사용한다. 단독 기반 모델과 어댑터를 해제한 기반 모델은 다른 캐시 지문을 쓴다. 모든 후속 산출물은 원 216장 대응 집계와 별도다.

v2 supervisor가 호출하는 Windows 실행기는 로컬 `data/fold0-crosssplit-visual-review/fold0-group-exclusions-confirmed.json`을 자동 확인한다. 마스크 파일의 고정 SHA-256과 판정 상태, 원래 개발 manifest의 SHA-256이 모두 맞아야 적용한다. 216장 대응 집계 직후 공식 원본 대 후보의 34장 민감도를 따로 저장하고, 재판독과 선택된 zero-shot 이후에는 동일한 34장에 공식 원본·후보·하이브리드를 비교한 두 번째 파일을 저장한다. 집계기는 세 출력 모두의 원래 216장 범위와 제외 링크의 그룹·fold를 확인한 뒤 동일한 사진을 제외한다. 기존 216장·36장 평가와 학습 분할은 유지한다.

확정 마스크는 2그룹 182장을 제외해 34장·34그룹을 남긴다. 제외된 두 그룹에 사진이 몰려 있었으므로, 작은 잔여 집합의 결과만으로 후보 승격이나 초기 평가 결론을 결정하지 않는다. [그룹 민감도 집계기](../kwater_lab/fold0_group_sensitivity.py)

이번 변경에서는 새 GPU 생성이나 학습을 실행하지 않았다. 새 run의 제안·수용률, 정확도 변화 및 타이밍은 실제 후속 작업이 끝난 뒤에만 기록한다.
