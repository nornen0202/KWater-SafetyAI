# Phase 2 모델 선정과 비교 실험

2026년 11월 26일 · K-water 현장사진 위험 판독 · 항목 38

**첫 비교는 공식 Qwen3-VL-4B가 놓친 위험을 경량 SigLIP 2가 찾는지, Qwen 혼자 같은 사진을 한 번 더 보는 것보다 이득이 있는지다. 첫 생성 모델 도전자는 Qwen3.5-4B의 새 11종 LoRA다.** 어느 쪽도 아직 제출 후보로 선정하지 않았다. 아래 파일 크기는 배포사가 제공하는 가중치 용량을 십진 GB로 더한 값이다. 대회 ZIP, 학습 최대 VRAM, 추론 메모리에는 각각 별도 측정이 필요하다.

## 어디에서 점수를 얻을 것인가

공식 총점 기준선은 Qwen과 운영사 어댑터의 42.04점이다. 170장으로 훈련한 CLIP·SigLIP 분류기와 고정 문구의 16.12점에는 후보 모델, 최종 위험 선택, 생성 방식의 효과가 함께 들어 있다. Phase 1에서는 대형 듀얼 인코더를 써도 같은 임계값 조건에서 단일→다중 스케일의 증가가 0.0030에 그쳤다. 반면 노출 18장에 두 모델의 예측을 연결하면 Qwen의 미탐 11건 중 9건이 듀얼 인코더 후보에 들어 있었고, 새 후보 40건 중 31건이 오탐이었다. **후보에 정답을 넣는 능력과 거짓 후보를 걸러내는 능력**을 각각 측정해야 한다. 총점의 다른 30점은 사진 근거·예방수칙·출처에서 나오므로, 생성기의 경제적인 개선도 경쟁 경로로 둔다. [기존 쌍체 진단과 채점 설계](phase2-3-public-score-experiment-design-20261126.md) · [공식 규칙](https://hackathon.imaginationgroup.co.kr/kwater/api/report)

### 무엇을 고정하고 무엇을 바꿀 것인가

1. **후보 비교.** 동일한 이미지에 기본 Qwen, 무힌트 2회 판독, 실제 후보 1개, 빈도·길이를 맞춘 교환 후보 1개를 배정한다. 정답의 상위 후보 포함률과 최종 회수율을 구분하고, 추가 오탐·원래 정답 손실·중대 위험·실행시간을 함께 기록한다. 가짜 후보도 비슷하게 채택하면 이미지 근거가 부족하다.
2. **모델과 학습 분리.** 3-VL-4B와 3.5-4B 각각에서 공식 학습자료로 새로 적합하기 전과 후를 비교한다. 체크포인트별 채팅 템플릿은 그 모델의 공식 형식을 쓰고 의미적 지시·허용 출력·정밀도·실제 픽셀/토큰 예산은 최대한 맞춘다. 11종 변환, 학습 횟수, 이미지 수, 판단 토큰 가중치를 기록한다. 3.5의 사고 토큰은 짧은 구조화 출력과 경쟁하므로 설정을 명시하고 잘려서 실패한 응답도 집계한다. QLoRA에서 실제 gradient와 어댑터 변경·재로딩을 검증한다. [QLoRA 논문](https://arxiv.org/abs/2305.14314) · [Qwen3.5-4B 사용 지침](https://huggingface.co/Qwen/Qwen3.5-4B)
3. **예산 문제를 먼저 드러낸다.** 같은 개발용 소표본에서 후보별 회수 건수/분, GPU 최고 메모리, 구조화 출력 실패, 추가 모델의 고정 로딩비를 측정한다. 좌우 채점 가능한 이미지에만 분모를 맞춰 실패한 조건을 유리하게 만들지 않는다. 기존 18장은 회귀·탐색, 새 64장은 원인 진단, 개발 920장 고정 그룹 OOF는 후보 선택용이다. 자원이 부족하면 후보 수부터 줄여 같은 평가 표본을 보존한다.
4. **정량과 설명을 교차한다.** Qwen/비전 분류기의 코드 집합에 이미지 기반 생성/고정 문구를 교차한다. 같은 코드 집합의 F1이 달라지면 출력 유효성부터 조사한다. 조문은 별도 정책으로 고정하거나 따로 시험한다. 사람 눈가림 평가 결과, 자동 대리지표, 공식 정성 점수는 각각 기록한다.
5. **승격 조건.** 통제된 개발 지표에서 기존 Qwen 대조보다 ΔF1 ≥0.02, 그룹 쌍체 구간 하한 >0, 무위험 오경보 비악화, 중대성 4 완전 미탐 감소를 확인한다. 단순한 모델과 효과가 비슷하면 작고 빠른 쪽부터 L4 검증에 올린다. 배포 LoRA나 전량 학습 모델을 보류 125장 독립 검증의 시작점으로 쓰지 않는다. 모델을 고정한 뒤 920장만 학습한 버전으로 보류 평가, L4 오프라인 200/300장 30/60분 리허설을 통과해야 제출 후보로 삼는다.

이번 선정은 공개 모델과 저장된 실험에 근거한 우선순위다. 새 어댑터의 F1, 실제 Linux L4 시간, 점수 상승폭은 실측 결과가 나온 뒤 이 판단을 갱신한다.
