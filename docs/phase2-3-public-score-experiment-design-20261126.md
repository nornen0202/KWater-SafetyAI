## Phase 2의 검증 순서

### 1. 배포본 재현과 독립성 확보

1. **배포 동작 비교**에는 1차 ZIP 그대로, 2차 ZIP 그대로, 공식 예시 10장과 기존 노출 18장의 저장 출력을 쓴다. 모델·어댑터·프롬프트·디코딩·후처리·법령 색인 지문을 기록한다. Qwen의 원생성, 최종 코드, 형식 복구, 무위험 판정, 파싱 실패에 따른 대체를 구별한다. 1차 그대로 돌렸을 때와 같은 입력에 같은 코드·동일한 형식이 나오는지 먼저 본다.
2. **성능 비교**에는 출처·시각 중복으로 묶은 개발 920장·29그룹의 고정 외측 5-fold를 쓴다. 공식 배포 LoRA는 제공 학습자료로 학습했다. 정확한 학습 ID가 없는 상태에서 이 LoRA나 해당 사례 인덱스를 쓴 결과에는 노출 가능성이 있다. 독립 비교용 8종 Qwen도 원천 기반 모델에서 각 외측 훈련 그룹만으로 학습한다. 새 11종 어댑터, 검색 사례, 교사·선호쌍, 후보 헤드도 같은 경계를 따른다. 법령 본문은 제공 원문으로 고정한다. 8종과 11종의 비교 상대는 같은 학습 예산의 모델이다.
3. 비용상 공식 생성기를 920장 모두에 여러 번 돌리기 전, 저장된 출력과 이미 노출된 사진으로 입출력 시험을 끝낸다. 다음으로 개발 그룹 전반에서 고정 시드로 소규모 진단 패널을 추출한다. **제안 규모는 64장**이며 기준선과 후보가 일치·불일치하는 사진, 경보 없음, 높은 위험 사례를 포함한다. 사진 배정과 추출확률을 저장한다. 불일치 사례를 많이 뽑은 표본은 원인 분석용이다. 전수 OOF 점수와 별도 표기하고, 성능 승격은 같은 920장 쌍체 비교로 결정한다.
4. 125장·4그룹은 봉인한다. 실제 사고·장소 ID의 비중복은 공식 확인되지 않았으므로 보고서에는 출처·시각 분할로 표기한다. 기존 Phase 1의 전량 1,045장 가중치나 기존 170장 전체로 적합한 2차 헤드도 외측 검증용으로 재사용하지 않는다. [분할·모델 구분](phase01-development-oof-and-full-fit-20261126-2155e8fa.md) · [공식 배포 설명](https://hackathon.imaginationgroup.co.kr/kwater/api/report)

### 2. 생성기를 고정한 후보 실험

**먼저 Qwen이 낸 기존 코드를 보존하고, 사진당 추가 후보를 최대 한 개만 허용한다.** 이미 코드 세 개가 나오면 첫 실험에서는 교체하지 않고 밀려날 후보만 기록한다. 확인 질문에는 위험 이름과 반증 가능한 시각 조건을 함께 준다. 예를 들어 높이차 추락에서는 단부·개구부, 작업자의 위치, 방호 상태가 어디에 보이는지를 묻는다. 판독 결과는 채택·기각·판단 곤란으로 나누고, 기각·판단 곤란이면 원출력을 유지한다. 새 근거를 지어내야만 후보를 채택할 수 있는 프롬프트는 쓰지 않는다. 공식 8종 내부 검증기에 없는 코드는 처음에는 기록만 하고, 11종 직렬화 검증이 끝난 실험에서 따로 다룬다.

| D | C와 같은 대상·호출 수에서 다른 사진 후보를 고정 순열로 제시 | 사진별 신호와 모델의 후보 추종을 구별 |
| E | C가 유효할 때 후보 제공자만 Phase 1 분류기로 교체 | 무거운 모델의 추가 회수량과 비용 |

C·D의 후보 개수·빈도·텍스트 토큰 예산을 맞추고 같은 그룹의 유사 사진 교환은 피한다. 우연히 정답 후보가 된 교환은 기록한다. 생성 시드·순서·길이 상한, 입력 해상도, 근거 작성 방식은 고정한다. 재판독할 행은 대조군을 보기 전에 고정한다. 후보가 없거나 출력 변화가 없는 행도 전체 분모에 넣는다. 마스크 해제와 잘못된 근거 생성의 영향을 따로 측정하기 위해 변경 전·후 코드, 채택 근거와 대체·탈락 사유를 저장한다. 후보로 제시한 물체의 존재를 그대로 믿는 경향은 시각질의 연구에서 측정 대상이 된 현상이다. 여기서는 사진 간 교환과 방호 상태가 다른 실사쌍으로 직접 검정한다. [후보 프롬프트 파일럿](../reports/full-image-prompt-pilot.md) · [시각 언어 모델의 환각 평가, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.20/)

**첫 산출물**은 모델별 순위표보다 *어떤 사진을 바꿨는가*를 보여주는 표다. Qwen이 놓친 정답 중 후보가 제안한 수, 검토를 거쳐 실제로 회수한 수, 새로 만든 FP, 기존 TP 중 잃은 수, 무위험→경보, 심각도 4 완전 미탐, 3개 상한 때문에 못 넣은 수를 코드별·그룹별로 센다. 후보가 정답을 전혀 포함하지 못하면 제안기를 바꾸고, 포함했지만 C가 D를 이기지 못하면 확인 프롬프트 또는 재판독 경로를 중단한다.

### 3. 25.92점 하락 원인을 분해하는 2×2 비교

같은 사진에서 원래 Qwen 코드 집합과 2차 방식의 코드 집합을 각각 저장한다. 개발 비교에는 fold 안에서 적합한 상대 모델을 사용한다. 각 집합에 대해 **사진을 보는 Qwen 설명**과 **2차의 코드별 고정 문구**를 교차한다. 네 칸 모두 같은 코드 집합 내에서 장면·코드 순서·위험도·출처 정책을 고정한다. Qwen이 쓰기 단계에서 코드를 바꾸지 못하게 하고 지정된 위험의 시각적 근거를 찾지 못하면 기록한다. 두 ZIP 원본을 별도로 보존한다. 통제한 네 칸에는 원본과 다른 조립 과정이 들어갈 수 있다.

- 같은 행 안에서 텍스트만 바꿨을 때 Macro F1은 같아야 한다. 달라지면 출력 파싱·무효 행·코드 변경부터 조사한다. 같은 열에서 코드 집합만 바꿨을 때 설명까지 어떻게 영향을 받는지 본다.
- 코드가 맞는 사진만 골라 글을 평가하면 거짓 위험을 설득력 있게 설명한 비용이 빠진다. 전체 샘플 평가와 두 검출기가 같은 코드를 맞힌 부분집합 평가를 나란히 둔다. 사진·예측만 본 평가자 두 명이 모델명과 좌우 순서를 모른 채 근거·예방·출처를 각각 0~3으로 채점한다. 무응답, 부적합, 동점, 불일치를 모두 남기고 사진에 없는 시설·방호 결여 단정, 위험한 조치, 근거 없는 인용은 별도 집계한다. 공식 비중 12·12·6으로 환산한 값은 **로컬 대리지표**로 표기한다.
- 법령 모듈은 코드·문장이 고정된 상태에서 별도 비교한다. 코드별 최빈 → 훈련 fold 사례 검색 → 조치·조문 지지 확인 순서로 본다. 공식 ID 허용 목록, 인용 정확도와 인용률, 실제 조치 지지 여부를 함께 잰다. 근거가 약하면 0개도 허용한다. 23건에서 첫 조문 적중이 10→2로 줄었던 조치 재정렬을 기본값으로 승격하지 않는다. [근거·예방 눈가림 설계](preference-pilot.md) · [실제 생성문 조문 비교](../reports/synthetic-and-law-2026-11-26.md)

### 4. 11종 미세조정과 희귀 위험

먼저 전체 자료 942개 주석의 11종 왕복 변환과 공식 형식을 점검한다. 학습용 분할별 총계도 대조한다. 8종 축소 과정에서 사라졌던 3종과 `other`의 차량 접촉 편중을 수정한다. **8종 대조군과 11종 기본 SFT**를 같은 출발 체크포인트·fold·토큰 예산에서 비교한다. 이후 결정 토큰 손실 1×→6×, 해상도 상한, 상위 비전 블록/프로젝터 LoRA를 한 번에 하나만 바꾼다. 각 단계에서 희소 코드 오탐·빈 응답·코드별 TP/FN·peak VRAM·실행시간을 같이 측정한다. 6×와 고해상도는 원래 로드맵의 후보값이다.

희귀 코드의 양성은 전체에서도 각 1장이다. 음성에서 오탐을 얼마나 줄였는지 확인할 수 있지만 단일 양성으로 일반화 재현율을 추정할 수 없다. 기존 fold의 저장 로짓에서 양성 그룹 1개일 때 **추가 제안만 억제**하는 조건, 기본 희소군 임계값 조건을 대조한다. 사전확률 보정을 제거하는 조건이 학습 손실을 바꾸면 캐시된 특징으로 해당 fold의 헤드를 다시 적합한다. Qwen이 스스로 발견한 위험까지 무조건 지우지 않는다. 진짜 현장 대조쌍에서 방호 상태가 바뀔 때 점수가 올바른 방향으로 움직이는지 확인한다. 외부 라벨을 쓰려면 12/6까지 신고 조건과 데이터별 이용 조건을 충족해야 한다. AI-Hub 라벨의 기존 증가분은 순열 대조보다 작았으므로 기본 트랙은 공식 자료만 사용한다. [외부 자료 비교](../reports/external-first-experiment.md) · [공식 규정](https://hackathon.imaginationgroup.co.kr/kwater/api/report)

DPO는 기존 26개 문구 쌍에 독립 선호 판정이 없다는 점을 먼저 해결한다. 개발 **훈련측**에서 사실 지지·조치 적절성을 눈가림 판정하고 합의·동점·제외·코드별 커버리지를 남긴다. 정답과 OOF 오류를 쌍으로 쓰더라도 같은 사건의 평가 라벨을 그 사건을 예측하는 모델의 훈련에 넣지 않는다. 사람이 어느 쪽을 선호하는지 재현되지 않거나 유효 쌍 수가 부족하면 SFT에서 멈춘다. 충분할 때만 동일 기초 SFT와 SFT+DPO 한 조건을 비교한다. [DPO 원 논문](https://proceedings.neurips.cc/paper_files/paper/2023/hash/a85b405ed65c6477a4fe8302b5e06ce7-Abstract-Conference.html)
