## 기존 지시의 이행 상태

Grounding DINO Base는 개발 사진 16장에서 실제 실행했다. 사람과 위험 대상이 함께 검출된 사진은 Tiny 0장, Base 1장이었고 매달린 하중은 양쪽 모두 0장이었다. CPU 처리 시간은 각각 91.63초와 313.02초였다. SAM 2.1 Tiny가 마스크를 낸 사진은 16장 중 2장이다. 박스를 받지 못한 사진에서는 큰 분할기로 바꿔도 그 경로의 입력이 생기지 않는다. 이 때문에 이미지에서 대상 자체를 찾는 SAM 3 직접 검출과, 같은 박스에서 마스크만 정교하게 만드는 효과를 각각 측정한다. [16장 원장](../data/phase2-runs/p38-20261126-49bb82ce/regions/tiny-vs-base16.json)

이 시점까지 신규 Qwen 4B·9B와 27B의 배포 크기 검토 기록은 있다. 공식 Qwen3-VL-4B와 LoRA의 실생성은 확인했다. 17시 44분부터 공식 8B(0c351dd0), 9B(c2022362), SAM 2.1 Large(665f8e2a) 가중치와 비교용 그래프 다운로드를 시작했고, 각 로컬 폴더와 받은 파일을 확인했다. 다음 순서는 Large의 공개 예시 및 같은 박스 16장, 8B·9B의 무적응 11장과 각각 32장·16회 QLoRA 업데이트다. 대형 Qwen 학습 업데이트·대회 사진 성능, SAM 3 위험 점수는 미측정이다.

## 실행과 채택 판정

1. **생성기 교체** — 동일 학습 그룹, 데이터·업데이트 수, 이미지 해상도와 출력 토큰 예산으로 기존 공식 4B+LoRA, 같은 계열 8B, 새 세대 3.5-4B·9B를 비교한다. 신규 기반은 적응 전과 자체 LoRA 적응 후 예측을 모두 보존한다. 학습에 필요한 메모리와 제출 때 추론에 필요한 메모리를 각각 기록한다.
2. **이미지 보강** — 같은 개발 16장에서 원본 RGB, 원본과 박스 크롭, 원본과 실제 마스크, 면적을 맞춘 교환 마스크를 비교한다. SAM 3 직접 탐지는 DINO가 박스를 내지 못한 사진까지 포함한다. 검출 건수와 함께 위험 코드 회수·새 오탐·시각적으로 맞는 근거 문장을 기록하고, 개선 후보를 개발 64장으로 확대한다.
3. **대회 적합성** — 패키지에는 가중치·토크나이저·어댑터·Linux 휠·고지를 포함한다. 공식 오프라인 환경에서 설치, 최초 모델 로드, 사진당 p50/p95, 최대 VRAM, 전체 처리 시간을 각각 기록한다. Public 200장/30분, Private 300장/60분은 설치와 로딩을 포함한다. 같은 L4에서 그 전체 경로를 실행한 뒤 통과 여부를 판정한다. [대회 안내](https://hackathon.imaginationgroup.co.kr/kwater/#rules)
4. **개선의 기준** — 개발 그룹 쌍체 Macro F1, 중대성 4 완전 미탐, 무위험 오경보, 판단 근거·예방조치·출처 품질을 함께 평가한다. 훈련 자료가 없는 그룹과 기존 탐색에 쓰인 그룹의 값을 각각 남긴다. 보류 125장에는 모델 선정이 끝난 뒤 독립 평가를 적용한다.

연구 전용 모델을 준비하는 동안 11월 26일 첫 제출에는 이미 실제 출력을 검증한 공식 4B+LoRA와 조문 선택 변경을 사용한다. 대형 후보의 첫 이미지 처리, 첫 LoRA 업데이트, 실제 완성 ZIP, L4 측정값은 항목 38 실행 원장에 단계별로 기록한다.

## 18시 22분 후속 실측과 접근 상태

Hugging Face 인증을 설정한 뒤 SAM 3와 SAM 3.1의 공식 가중치 접근을 각각 재확인했다. 두 응답 모두 403이고 제작사가 접근 신청을 심사하고 있다고 명시했다. Meta의 단일 JPG 벤치마크는 사진마다 세션을 열고 첫 프레임에 프롬프트를 넣는다. 이 경로로 SAM 3.1과 SAM 3를 같은 입력에서 비교하고, 컴파일·모델 로딩 시간과 사진별 처리 시간을 나눠 기록한다. [공식 사진 벤치마크](https://github.com/facebookresearch/sam3/blob/main/scripts/bench_compile.py) · [공식 모델 빌더](https://github.com/facebookresearch/sam3/blob/main/sam3/model_builder.py)

같은 Base 검출 박스를 사용한 16장에서는 SAM 2.1 Tiny와 Large 모두 6장에서 호출됐고 10장은 원본 RGB로 복귀했다. 호출 CPU 시간 합은 23.32초와 123.09초, p50/p95는 Tiny 3.40/5.73초, Large 18.67/38.98초였다. 첫 개발 사진에서 두 모델 마스크 간 IoU는 0.8454다. 실제 정답 마스크와 위험 점수 차이는 별도 검증 대상이다. [실측 원장](../data/phase2-runs/p38-20261126-49bb82ce/regions/base-sam-size/engineering.json)

대형 Qwen과 비교용 4B의 32장·16회 업데이트는 학습 연결을 확인하는 단계다. 다음 단계는 동결 64장과 그룹 중복이 없는 170장·6그룹의 85회 적합이다. 이후 유망 기반은 사전 지정 외측 fold 1을 떼고 727장·23그룹으로 적합해 미노출 175장·5그룹에서 비교한다. [분할 원장](../data/phase2-runs/p38-20261126-49bb82ce/large-models/expansion-outer1.json)

## 동일 예산에서 DINO와 결합 제안기가 다르게 선택한 사진

개발 전용 920장의 기존 그룹 외측 예측을 사진별로 짝지었다. DINO 단독과 DINO·SigLIP 결합에 각각 위험 코드 한 개를 제안할 기회 230회를 줬으며 두 모델 모두 사용한 사진, 한 모델만 사용한 사진을 구분했다. 보류 125장은 집계에 포함하지 않았다. [개발 예측 원장](../data/phase2-runs/p38-20261126-49bb82ce/matched-budget-predictions.json)

| 두 제안기의 선택 | 사진 | DINO 정답 제안 | 결합 정답 제안 |
|---|---:|---:|---:|
| 같은 사진·같은 코드 | 143 | 115 | 115 |
| 같은 사진·서로 다른 코드 | 10 | 7 | 7 |
| DINO만 제안 | 77 | 43 | 0 |
| 결합만 제안 | 77 | 0 | 50 |
| 양쪽 모두 제안 없음 | 613 | 0 | 0 |
| 합계 | 920 | 165 | 172 |

결합의 순증 7건은 **어느 사진에 제안할지**가 달라져 생겼다. 같은 사진에 서로 다른 코드를 제안한 열 장에서는 양쪽 모두 일곱 건씩 맞았고 네 장은 두 위험이 모두 정답이었다. 그룹 하나씩 제외한 순증은 +5~+10건이지만, 29개 그룹을 복원추출한 10,000회 쌍체 부트스트랩에서 정답 제안 수 차이의 95% 구간은 −6~+20건이었다(시드 42, 각 재표본은 그룹 크기를 따름). 결합 제안기는 추락 정답이 47→56개, 기타가 17→33개로 늘고 걸림·넘어짐은 78→61개로 줄었다. 위험 코드별로 이득이 다르며 이 수치는 제출 점수로 환산할 수 없다.

기존 Qwen 재판독에서는 같은 호출 예산을 유지하면서 **Qwen이 원래 놓친 위험 중 실제로 회복한 개수**, 기존 정답 손실, 새 오탐을 위 구간별로 집계한다. 양쪽 제안기가 모두 침묵한 613장 중에도 위험 정답이 있는 사진이 341장이다. 따라서 보조 제안기가 조용한 사진에도 공식 Qwen의 원래 판독을 그대로 수행한다. 두 모델이 서로 다르게 제안한 경우는 복합 위험을 별도로 집계한다. 이번 집계로 이미 고정한 평가 패널이나 임계값을 변경하지 않는다.


## 공식 Qwen 원판독에서 실제로 보완할 수 있었던 위험

11월 26일 두 번째 제출을 접수한 뒤, 동결 64장 중 그때까지 원생성이 저장된 28장·23그룹을 개발 정답과 연결했다. 공식 Qwen이 정답 위험 31건 중 15건을 맞히고 16건을 놓쳤으며, 잘못 제안한 코드는 5건이었다. 개발 920장 전체에서 모델당 230회로 고정한 제안 정책을 그대로 사용해, 이 28장에서 Qwen 출력과 겹치지 않고 세 슬롯 안에 들어갈 코드만 셌다. 미완료 36장은 집계하지 않았다. DINO와 결합의 새 제안을 합쳐 사진·코드 중복을 제거하면 세 건이다. 정답을 미리 아는 판독기가 두 모델의 새 제안을 완벽하게 걸러도, 이 조건에서 Qwen이 놓친 16건 중 13건은 남는다. 남은 정답은 걸림·넘어짐 5, 추락 3, 기타 3, 끼임 1, 인양물 충돌 1건이다. 중대성 4 정답을 하나도 맞히지 못한 사진은 11장 중 5장이고, 완벽한 후보 선택을 가정해도 4장이 남는다. 실제 재판독이 그 한 장을 회복했는지는 후속 실측에서 판단한다.

이 결과에 따라 보조 제안의 정밀도와 별도로, 더 큰 Qwen과 LoRA가 **제안기 없이 처음부터 찾는 위험**을 비교해야 한다. 원판독, 제안기의 이론상 추가 회수, 실제 재판독 후 순회수를 같은 사진에서 각각 기록한다. 이 부분 집계는 공식 어댑터가 학습한 자료에서 나온 진단이며, 사용 가능한 공식 Public 점수는 총점뿐이다.

호출 예산을 진단용으로 풀어 두 제안기의 1위 코드를 **28장 모두**에서 확인했다. 두 제안기의 코드를 사진별로 합치고 기존 Qwen 코드와 중복을 빼면 새 후보는 정답 9개·오탐 20개였다. 기존 230회 예산에서 보이던 정답 3개에 비해 추가로 확인할 수 있는 정답은 6개(추락 2, 걸림·넘어짐 2, 기타 1, 끼임 1)다. 새 오탐 후보는 16장에 생겼고, 그중 원판독이 올바르게 무위험으로 둔 사진이 4장이었다. 28장 모두에서 원판독과 추가 후보의 합은 세 슬롯 이내였다.

따라서 Qwen 미탐 16건은 현재 예산에서도 후보에 있는 3건, 두 제안기의 1위에 있지만 호출 예산 때문에 빠진 6건, 예산을 풀어도 두 제안기의 1위에 없는 7건으로 나뉜다. 첫째·둘째 유형은 후보 검증기의 회복과 오경보 억제를 측정하고, 셋째 유형은 더 큰 생성기의 원판독이나 다른 시각 정보가 추가 증거를 주는지 비교한다. 전체 호출에서 나온 수치는 가능한 제안의 범위이고, 실제 사진에서 20개 오탐을 걸러냈다는 의미는 아니다.

## LoRA 학습 단계 사이의 사진·그룹 중복

같은 920장의 개발 등록부에서 파일럿 32장, 패널 비교용 170장, 첫 외측 폴드용 727장의 학습 ID를 각각 고정된 평가 ID와 대조했다. 표의 두 수는 평가 사진 가운데 **학습 사진 자체가 다시 나온 수 / 학습 사진과 같은 그룹에 속한 수**다. 그룹 중복 수에는 같은 사진도 포함된다. 보류 125장은 열지 않았다. **32장→11장, 170장→64장, 727장→175장**은 각 실험을 독립적인 새 기반 모델에서 시작하면 학습·평가 그룹이 분리된다. 32장 파일럿의 어댑터를 이어 학습하면 외측 175장 중 12장은 이미 그 어댑터가 학습한 사진이고, 173장은 학습 그룹과 겹친다. 기존 175장과 외측 폴드를 유지하면서 각 실험의 기반 가중치 리비전, 부모 어댑터, 누적 학습 사진 및 그룹을 확인한다. 175장을 특정 모델에 대해 독립이라고 표기할 때 해당 모델의 학습 계보를 명시한다. 727장 적합 후의 64장 패널 점수는 그중 48장이 학습과 겹치므로 독립 검증값으로 쓰지 않는다.

32장 파일럿에서는 10개 양성 유형 중 7개가 각각 한 사진·한 그룹에만 있다. 170장은 전체 장수가 늘어도 양성 유형이 7개이고, 감전과 화재·폭발은 각각 1장·1그룹이다. 727장에서도 익사·침수는 1장·1그룹이다. 따라서 대형 모델과 비교용 4B는 같은 단계·같은 평가 집합에서 비교하고, 유형별 양성 사진 수와 그룹 수를 F1과 함께 제시한다.

28장은 이미 위험 누락을 분석한 개발 표본이다. 남은 36장은 Qwen 출력이 생기기 전에 규칙을 고정했다. 그중 두 분류기가 같은 후보를 내는 사진은 최대 14장이고 실제 추가 수는 Qwen의 기존 코드에 따라 달라진다. 이 36장의 22개 그룹 모두 앞선 28장에도 나오므로 별도 사진에서의 재현과 새 그룹 일반화를 구분한다. 다음으로 분류 점수와 함께 사진에 맞는 판단 근거·예방조치를 생성할 수 있는지, 그 호출을 포함한 L4 시간이 허용되는지를 확인한다. 현재 수치는 코드를 재생한 개발 지표이며 공식 제출 점수는 42.04다.
