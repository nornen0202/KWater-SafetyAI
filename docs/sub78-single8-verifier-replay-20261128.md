# Fold 4의 8B 검증기 비교

8B BF16 첫 에폭 초벌 및 전문가 후보 52건을 고정한다. 공유 방식은 첫 에폭 어댑터로 검증하고 전환 방식은 동일 8B 기반모델에 둘째 에폭 어댑터를 올려 검증한다. 검증 단계만 바꾸며 기존 초벌이나 법령 선택을 다시 실행하지 않는다. 두 팔 모두 같은 정밀도, 배치 2, 393,216 픽셀 상한, 최대 280 생성 토큰, seed 42, 탐욕 디코딩을 사용한다. 실제 GPU·추론 속도·VRAM은 사전 점검에서 측정하지 않았다.

두 팔에서 각각 52건의 이미지 및 위험 코드별 `logit(accept)−logit(reject)`와 전체 검증 응답을 저장한다. 그러면 마진 탈락과 생성 기각·형식 오류를 개별 비교할 수 있다. 최종 위험 코드에 추가하려면 기존 4B 내측 OOF 결합 게이트와 엄격한 생성 승인 조건을 동시에 충족해야 한다. 이 고정 게이트는 8B에 옮긴 탐색 진단 조건이다. 두 8B 어댑터나 NF4의 마진 보정값으로 해석하지 않는다. Fold 4 정답은 CPU 채점에서만 사용한다. 채점은 175장·39그룹, 교차 현장 제외 107장·36그룹, 최대 잔존 그룹 제외 58장에 대해 정상 오경보·심각도 4 완전 미탐·위험 코드 F1·두 어댑터 간 그룹 부트스트랩을 내며 6차와 8B 단독도 대조한다. 기존 4B 검증 참조는 Windows 47건과 서울 L4 5건을 합친 별도 측정이다. 이 실험은 공식 제출 코드에 포함하지 않는다.

## 로컬 실행

1. CPU에서 `python -B -m kwater_lab.sub78_single8_verifier freeze`를 실행한다. 명령이 출력하는 SHA-256을 후속 두 단계에 사용한다. 캐시의 원생성·175장 순서·동결 선택기·프롬프트·52개 실제 사진과 체크포인트 설정을 해시한다. 모델 가중치는 기존 로컬 원장을 기반으로 실제 파일 길이와 원본 LFS SHA-256(기반모델) 또는 실행 영수증 SHA-256(LoRA)을 대조한다. 가중치 바이트의 재해시는 GPU 측정 단계가 모델을 적재하기 전에 수행한다. 비공개 파일 `data/local-eval-predictions/sub78-single8-verifier/manifest.json`에는 후보·이미지 지문 및 입력 파일 SHA만 저장한다. 원시 응답과 사진 식별자는 로컬에 보관한다.
2. GPU가 비면 `python -B -m kwater_lab.sub78_single8_verifier measure --precision nf4 --manifest-sha256 <SHA>`를 실행한다. `bf16`은 별도 조건이다. `nf4`는 언어 모델 가중치를 NF4 이중 양자화하고 BF16으로 연산하며 비전 모듈과 출력 헤드는 BF16에 둔다. 고정 첫 에폭 BF16 초벌을 사용하므로 이 결과를 NF4 종단 배포 검증으로 간주하지 않는다. 한 팔의 52건이 전부 끝날 때 영수증을 남겨 결과를 보존하며, 같은 런타임으로 재개할 수 있다. 실행은 실제 기반파일 SHA를 읽어서 확인한다.
3. CPU에서 `python -B -m kwater_lab.sub78_single8_verifier score --precision nf4 --manifest-sha256 <SHA> --output results/sub78-single8-verifier-nf4.json`로 공개 가능한 집계만 재생한다. 각 팔의 52건이 순서까지 일치해야 한다. 두 팔의 런타임 또는 요청된 정밀도·가중치가 다르면 채점하지 않는다. CPU 단계에서 `CUDA_VISIBLE_DEVICES=-1` 및 `OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`을 사용했다.

## 자원 조건

- 12 GiB RTX 3060에는 BF16 기반 가중치만으로 약 17.53 GB가 필요하므로 이 CLI의 단일 GPU BF16 적재가 불가능하다. NF4는 텐서 헤더에서 양자화 가능해 보이는 선형층의 BF16 13.89 GB를 이상적으로 4비트로 환산하고 나머지 3.64 GB와 FP32 어댑터 두 개 약 0.36 GB를 더하면 약 7.47 GB다. 이는 양자화 메타데이터, 적재 피크, 활성값, 캐시, 메모리 예약을 뺀 근사다. 12 GiB에서 배치 2 성공이나 적재 가능 여부는 미측정이다. 진단 전용으로 폴백 배치를 자동 적용하지 않는다.
- 기존 서울 L4의 8B BF16 초벌 175장 생성 실측은 1,057.1초였다. 이번에는 104번 마진과 104번 생성이 고정 작업량이다. 7차 4B 실측의 요청당 마진 0.788초와 생성 4.605초를 단순 대입하면 약 561초로, 이는 4B 참고 산술이다. 8B 검증·NF4·RTX 3060 속도, 모델 적재와 전환 시간은 미측정이다. 저메모리 조건에서 첫 실측값은 CLI가 적재·전환·마진·생성 시간을 나눠 기록하고 CUDA의 최대 할당·예약 메모리를 함께 기록한다.
