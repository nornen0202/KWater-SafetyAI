## 2. Phase 1~2 코드 및 멀티 에이전트 운영에서 발견된 4대 치명적 결함

코덱스 에이전트가 작성한 실제 파이썬 소스(`phase01_vision.py`, `phase01_head.py`, `phase01_data.py`)와 시스템 상태를 직접 대조한 결과, 왜 개발 920장 분류기조차 F1 `0.26~0.31`에 머물고 무위험 오경보가 `308/308(100%)`이 나왔는지 **명백한 구현 버그**가 확인되었습니다.

### 결함 1 [치명적 구현 버그]: `phase01_vision.py`(69~75, 131행)의 무작위 가우시안 차원 축소
```python
matrix = rng.standard_normal((width, 64), dtype=np.float32) / np.sqrt(np.float32(width))
tok = F.normalize((tok @ self.projection[name]).float(), dim=-1)
```
- 고성능 `SigLIP 2 So400m`(1,152차원)과 `DINOv2-Large`(1,024차원)를 불러와 놓고, **학습되지 않은 고정 난수 행렬(Random Gaussian Matrix)을 곱해 각각 64차원으로 강제 압축하여 원본 표현력의 94.4%를 학습 전에 파괴**했습니다.
- 게다가 패치 토큰도 `4×4` 평균 격자로 뭉갠 뒤 난수 투영을 걸어 미세 안전 단서가 모두 소실되었습니다.

### 결함 2 [치명적 수식 버그]: `phase01_head.py`(69행 vs 91행)의 학습-추론 로짓 부호 불일치
- **학습 시(69행)**: `p = torch.sigmoid(z + 0.5 * torch.log(prior))`로 확률을 계산합니다. 희귀 클래스($\pi_c \approx 0.0014$)는 $0.5 \log \pi_c \approx -3.30$이 더해지므로, 네트워크는 이를 상쇄하기 위해 원시 로짓 `z`를 **`+3.30`만큼 높게 출력**하도록 학습됩니다.
- **추론 시(91행 `logits()`)**: `0.5 * torch.log(prior)` 항을 빼먹고 **원시 로짓 `z`를 그대로 반환**했습니다!
- 그 결과 추론 시 희귀 클래스의 오즈(Odds)가 학습 대비 최대 **27배 부풀려져**, `drowning_inundation`(양성 1장)에서 **오탐 457건**, `confined_space`(양성 1장)에서 **오탐 543건**, `chemical_exposure`(양성 3장)에서 **오탐 623건**, 무위험 사진 오경보 **`308/308(100%)`**이라는 대참사가 발생했습니다. 코덱스는 오후 내내 이 수식 버그를 고치는 대신 "사전확률 계수 0 재적합 실험"이라는 이름으로 별도 보고서를 쓰며 시간을 허비했습니다.

### 결함 3 [치명적 분할 사고]: `phase01_data.py`(43~45, 88~104행)가 핵심 소수 클래스를 보류셋에 통째로 격리
- 서로 다른 현장에서 수집된 보강 사진 묶음인 `ADD*`(67장)와 `SBE*`(29장)를 각각 단일 그룹 1개로 묶은 뒤, **라벨을 보지 않는 부분합(`reserve`) 알고리즘**으로 125장 봉인 보류셋을 뽑았습니다.
- 그 결과 `ADD`(67장)와 `SBE`(29장)가 통째로 125장 봉인 보류셋에 들어가면서, 정작 모델 개발·학습에 쓰는 **920장 개발 풀에서 전체 `fire_explosion` 44건 중 37건(84.1%), `chemical_exposure` 19건 중 16건(84.2%), `electrical_energy` 47건 중 30건(63.8%), `thermal_weather` 1건 중 1건(100%)이 증발**했습니다(`phase01-development-oof` 79~84행 표에서 실증 확인).

### 결함 4 [심각한 자원 교착 및 모델 백화점식 산만함]: 22개 백그라운드 프로세스 동시 실행으로 학습 불발

### 왜 1위 팀은 벌써 58점에 도달했는가? (핵심 격차 +16점의 출처)
1. **8종 → 11종 스키마 족쇄 해제 및 `other` 프롬프트 복원 (+6 ~ +8점)**:
   - 주최 측 `prepare_dataset.py`와 `system_prompt.txt`를 열어 본 상위 팀들은 즉시 ① 3개 누락 코드(`confined_space`, `drowning_inundation`, `thermal_weather`)를 학습·추론 스키마에 복원하고, ② `other`(168건)가 차량 접촉(`collision_contact`)으로 잘못 정의된 것을 고쳐 **11종 네이티브 Qwen3-VL LoRA를 재학습**했습니다. Public 200장에 수자원공사 특유의 수조(`drowning_inundation`)나 맨홀(`confined_space`)이 단 2~3장만 있어도 8종 모델은 해당 코드 F1=0이지만, 11종 재학습 모델은 단숨에 코드당 F1 0.5~0.7을 얻어 총점이 5~7점 점프합니다.
2. **과소 탐지(51% 미탐률) 해소 및 고해상도(`max_pixels` 상향) 추론 (+5 ~ +6점)**:
   - 순정 베이스라인은 `384*32*32` 저해상도와 보수적 디코딩 때문에 로컬 키트 10장 중 8장을 무위험으로 내고, 개발 28장에서도 위험의 절반(16/31건)을 놓칩니다. 해상도를 `640*32*32 ~ 768*32*32`로 올리고 결정 토큰 가중 학습 또는 듀얼 분류기 후보 검증을 결합하면 정량 F1 상승(+4점)과 함께 **미탐에서 구제된 사진들의 정성 점수(+2~3점)가 동시에 따라 올라옵니다.**
3. **11종 법령 검색 색인 일치 및 프롬프트 구체화 (+2 ~ +3점)**:
   - `assets/train.jsonl`을 11종 코드로 재색인하고 근거·예방조치 작성 지침을 KOSHA 채점 기준(구체적 위치·객체·방호 결여 상태 + 즉시 실행 조치)에 맞추면 3종 LLM 정성 점수가 즉각 상승합니다.

### Step 0 [오늘 밤 즉시 · 30분]: 작업 환경 정상화 및 규정 위반 파일 격리
1. **백그라운드 좀비 프로세스 일괄 종료**: 현재 떠 있는 `phase2_*`, `item39_*`, `repair_aihub`, `verify_external_archives` 등 코덱스 백그라운드 프로세스를 모두 종료해 VRAM 12GB와 시스템 RAM 16GB를 완전히 확보합니다.
2. **대회 데이터 유출 방지 조치**: 원본 사진·라벨이 박혀 있는 미추적 `reports/kwater-progress-20261126*`, `docs/kwater-progress-20261126*`를 `data/local-reports/`로 이동하여 Git 커밋 사고를 원천 차단합니다.
3. **불필요 실험 전면 폐기 선언**: `SAM 2.1/3.0/3.1`, `Grounding DINO`, `Depth Anything`, `Qwen3.5/3.8-27B`, 정규식 후처리(`A`, `B2`)는 오늘부로 완전히 폐기합니다.

### Step 1 [내일~모레 · 목표 Public `50 ~ 54점` (단숨에 Top 10 진입)]: **11종 네이티브 고해상도 `Qwen3-VL-4B` 정석 재학습 (Submission #5)**

가장 확실하고 리스크가 낮으면서 기대 점수 상승폭(+8~12점)이 가장 큰 정공법입니다.

1. **결함 없는 표준 5-Fold 사건 분할 생성 (`kwater_lab/clean_split.py`)**:
   - `ADD*`(67장)와 `SBE*`(29장)를 단일 덩어리로 묶어 보류셋에 버리던 버그를 수정합니다. 실제 시각 유사도(`SigLIP2+DINOv2 코사인 ≥ 0.80` 또는 `ORB 기하 매칭`)가 있는 쌍만 같은 사건으로 묶은 뒤, `holdout-exclusions.json`(182장+연결 사건)을 제외한 미노출 사건에서 **클래스 비율을 보존하여 105장만 봉인 Holdout으로 분리**하고, 나머지 **940장(화재 ~39건, 화학 ~17건, 감전 ~42건, 끼임 ~43건 포함)을 5-Fold 다중라벨 층화 분할**합니다.
2. **11종 네이티브 데이터셋 & 교정 시스템 프롬프트 (`system_prompt_11code.txt`)**:
   - 942개 모든 위험 인스턴스를 공식 11종 코드 그대로 유지합니다(누락 행 0개).
   - `other` 정의를 실제 데이터에 맞게 복원(*"비계·거푸집·동바리·사면·구축물의 변형·붕괴 우려, 이동식 중장비·차량과의 접촉 위험, 위험 구역 출입통제 미흡, 돌출 철근·날카로운 자재 접촉 등 타 10종 외 가시적 위험"*)하고, `confined_space`·`drowning_inundation`·`thermal_weather`의 엄격한 시각 관측 기준을 명시합니다.
   - `notes.scene_note`를 활용한 **관찰 우선(`scene_note` → `scene_state` → `hazards`)** 출력과 **결정 토큰 가중치($5\times$: `scene_state`, `code`, `likelihood_score`, `severity_score`)**를 적용합니다.
3. **고해상도(`640×32×32`) Multimodal QLoRA 학습 → BF16 병합 추론**:
   - **학습 대상**: `language_model` 전 선형층 + **`visual.merger` 및 `visual.deepstack_mergers`**(DeepStack 시각-언어 연결부 개방!), `r=16, lora_alpha=32`, 3~4 에폭, 희소 클래스(`chemical`, `fire`, `electrical`, `caught`, 희귀 3종) 완만 과표집($\sqrt{\text{역빈도}}$).
   - **학습 시간**: 클린 상태의 RTX 3060 12GB(NF4 QLoRA + SDPA + grad checkpointing)에서 1개 폴드(~750장 × 3에폭 ≈ 140 step) 학습에 **약 2~2.5시간** 소요됩니다(팀 전용 비공개 클라우드 L4/A100 활용 시 25분 내 완료 — 대회 FAQ 허용 범위).
   - **추론 패키징**: 검증된 1차 베이스라인(`kwater-baseline.zip`)의 안정적인 오프라인 구조는 그대로 유지하되, ① 새 11종 LoRA 어댑터 교체, ② `CODE_MAP`을 11종 항등 매핑으로 변경, ③ `assets/train.jsonl`을 학습 폴드 11종 코드로 재색인(`LawRetriever` 11종 호환), ④ `max_pixels = 640 * 32 * 32`, `KW_BATCH = 8` 적용(L4 24GB에서 200장 약 14분 완주, ZIP 약 9.05GB).
4. **제출 승인 관문**: 외측 검증 폴드(~188장, 미학습 사건)에서 순정 8종 모델 대비 **활성 Macro F1 +0.05 이상**, **변경 사진 비율 25% 이상**, 무효 행 0건 확인 후 **5차 제출** 진행.

### Step 2 [Step 1 직후 2~3일 · 목표 Public `55 ~ 60점+` (Top 3 ~ 1위 경쟁)]: **버그 수정 듀얼 비전 전문가 + VLM 시각 검증 하이브리드 (Submission #6~#7)**

Step 1 모델이 여전히 놓치는 **다중 위험의 2~3번째 코드 및 원거리 개구부·인양 위험**을 정밀 회수합니다.

1. **Phase 1의 3대 버그를 모두 고친 진짜 듀얼 비전 분류기(`SigLIP 2 So400m-384` + `DINOv2-Large`)**:
   - 64차원 난수 투영 삭제 → **원본 2,176차원 전역 + 패치 어텐션 풀링(Query2Label 12쿼리) + 전역/2×2 타일 LSE 결합**을 학습 가능한 가중치로 적합.
   - 학습-추론 로짓 부호 일치 + 클래스별 온도·수축 임계값 + 전용 무위험 장면 게이트 적용(양성 그룹 ≤1인 희귀 코드는 분류기 단독 제안 금지).
   - 5개 폴드 헤드 앙상블의 개발 940장 OOF 목표: **단독 Macro F1 `0.46 ~ 0.52+`**, 무위험 오경보율 **18% 이하**.
2. **2단계 "후보 제안 → VLM 시각 근거 검증·생성" 결합**:
   - 1차로 Step 1의 **11종 `Qwen3-VL-4B`**가 전체 사진을 판독합니다.
   - 1차 출력 위험이 2개 이하인 사진 중, **5-Fold 듀얼 비전 앙상블이 고신뢰로 지목한 미출력 위험 후보 최대 1개**(`~25~35%` 사진에서만 발동)를 추립니다.
   - 자동 추가(무위험 오탐 유발) 대신, **후보 검증용 데이터(~800장 학습셋에서 추출한 양성 800건 + 동일 코드 하드 네거티브 800건 = 1,600건)로 함께 학습된 `Qwen3-VL-4B`**에게 `(사진, 후보 코드)`를 주어 **실제 시각 근거가 확인될 때만(`ACCEPT`) 해당 사진 맞춤형 `evidence`·`prevention`·`risk_level`을 생성**하고, 방호 설비가 완비된 안전 사진이면 기각(`REJECT`)합니다.
3. **용량 및 시간 예산**:
   - `Qwen3-VL-4B` BF16(8.9GB) + `SigLIP2-So400m` 비전 타워 전용 BF16(0.85GB, 미사용 텍스트 타워 2.8GB 제거!) + `DINOv2-L` BF16(0.61GB) + 어댑터·휠(0.2GB) = **총 ZIP `10.6 GB`**(20GB 한도의 절반).
   - L4 24GB 실행 시간: 비전 앙상블 200장(15초) → 메모리 해제 → Qwen 1차 200장(13분) + 후보 발동 ~60장 2차 검증 생성(3분) = **총 ~16.5분**(30분 한도 대비 충분한 여유).

### Step 3 [마감 전 고도화 · 목표 Public `58 ~ 63점+` 및 Private·결선 제패]: **OOF 하드 네거티브 DPO + 서브타입 법령 재정렬 + 5-Fold 어댑터 병합**

1. **OOF 실수 기반 반사실적 DPO(1에폭)**:
   - Step 1~2 모델이 OOF에서 실제로 틀린 3대 유형(① 무위험 사진 오경보, ② 바닥 전선→감전 과잉 추론, ③ `fall_height + slip_trip` 복합 위험 중 1개 누락)을 선호쌍 $(y^+, y^-)$로 묶어 1에폭 DPO 정렬을 수행합니다.
2. **11종 서브타입 법령 재정렬기(`OSH-3` vs `22`, `OSH-43` vs `56`, `OSH-52` vs `200` vs `20`, `OSH-4-2`)**:
   - 생성된 `evidence`+`prevention`과 조문 본문·사례집을 대조하여 가장 직접적으로 조치를 뒷받침하는 1~2개 조문을 부여해 출처 6점과 3종 LLM 정성 점수를 극대화합니다.
3. **5-Fold LoRA 가중치 병합(Adapter Soup / TIES-Merging)**:
   - 추론 시간을 1초도 늘리지 않으면서 5개 폴드 학습 지식을 단일 어댑터로 통합해 Private 300장 분포 이동(Distribution Shift) 강건성을 확보합니다.

## 6. 제출 관리 철칙 (남은 기간 슬롯 낭비 원천 방지 4원칙)

1. **최소 유효 변경률 게이트(Minimum Delta Gate)**: 미학습 검증셋(~185장 이상)에서 기준 모델 대비 **예측 코드 집합이 바뀌는 사진이 최소 10%(18장) 이상**이고, **활성 Macro F1이 최소 +0.03(+2.1점) 이상** 유의미하게 상승하지 않은 후보는 절대 제출하지 않습니다(3·4차 같은 0% 변경 제출 원천 차단).
2. **가중치 학습 우선 원칙**: 프롬프트 문구 손질이나 정규식 규칙만으로 단독 제출하지 않고, 반드시 **11종 학습 데이터로 실제 그래디언트 업데이트를 마친 모델**만 제출 슬롯을 부여합니다.
3. **단일 기준 벤치마크 고정**: 모든 후보는 동일한 **940장 5-Fold OOF(시간 제약 시 외측 Fold 0의 188장 고정 검증셋)** 한 곳에서 같은 공식 채점기(`kwater_lab/metrics.py`)로 일렬 비교합니다.
4. **컨테이너 실전 리허설 의무화**: 업로드 직전 반드시 공식 Docker 런타임(`run_local.sh`, `--network none`, `seccomp`)에서 `유효 결과 N/N`, 메모리 여유, 200장 환산 시간(≤ 22분)을 통과한 ZIP만 접수합니다.
