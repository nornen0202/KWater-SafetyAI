# Clean-Cal v2 적합측 전문가와 법령 사례집

동결한 Fold 4의 적합 709장·보정 82장과 Fold 2의 적합 631장·보정 138장을 사용한다. 이미지 SHA와 확인된 시각 연결에서 도출한 별칭 연결성분을 단위로 적합 데이터를 네 그룹 폴드로 나눈다. 각 내측 모델은 다른 세 폴드에서만 학습한다. 적합측 OOF 예측을 사진당 한 번 만들고, 별도 보정 사진은 적합 영역 안에서 학습한 12개 헤드 평균으로 예측한다. 외측 사진은 점수화하지 않는다. [동결 분할](sub78-clean-cal-design-20261128.md)

전문가 헤드는 기존 7뷰·2,176차원 구조, 55에폭, 배치 64, 세 시드를 그대로 사용한다. 시드 오프셋은 내측 폴드당 100이다. 원래 배포의 5개 폴드와 달리 여기서는 알려진 별칭을 보존하는 연구용 그룹 폴드 4개다. 고정된 외부 사전학습 SigLIP2·DINOv2 이미지 특징을 재사용한다. 캐시에 다른 사진의 특징도 있으나 학습기는 해당 내측 fit 이미지·정답·텍스트만 소비한다. OOF와 보정 예측은 각각 해당 이미지 특징만 소비한다. n-gram 어휘, IDF, 64차원 SVD, 레이블 사전분포와 가중치는 해당 내측 학습 행에서만 계산한다. 기존 전문가 점수와 정책 가중치는 읽지 않는다.

법령 사례집은 적합측 원래 정답과 법령 참조로 기존 compact exporter에서 생성한다. 적합 사례집의 입력 ID와 출력 SHA를 남긴다. 공식 법령 정본은 그대로다. 점수 파일을 만든 뒤 보정 정답을 읽으며, 보정 정답은 후보 수와 주석 지지 진단에만 사용한다. 고정 빈 초벌 진단에서 code/scene 기준은 각 .50이고, 기존 후보 선택기의 빈 초벌 마진 .12와 추가 scene 요구 .08을 그대로 쓴다. 사진당 최대 1건이며, code precision 보정은 적용하지 않는다. 새 임계값, 마진 및 검증기 승인을 선택하지 않는다.

    $env:CUDA_VISIBLE_DEVICES = '-1'
    $env:OMP_NUM_THREADS = '2'
    $env:MKL_NUM_THREADS = '2'
    $env:OPENBLAS_NUM_THREADS = '2'
    python -B -m kwater_lab.sub78_clean_cal_specialist --fold 4 2

한 헤드만 확인할 때는 --new-head-limit 1을 더한다. 같은 명령을 다시 실행하면 소스·동결 분할·특징·입력의 SHA가 일치하는 완료 헤드를 다시 읽는다. 헤드 체크포인트, 원본·예측 ID 대응, 법령 사례와 점수 배열은 data/local-reports/clean-cal-v2-fit-specialist/에만 둔다.

Clean-Cal 적합측 VLM 판독과 검증기는 새로 학습해야 한다. 종전 어댑터는 보정에 배정된 사진을 보았으므로 새 후보를 만들기 위한 대체물로 쓸 수 없다. 이 단계의 후보 진단에는 VLM 출력, 공식 배포 시간, 외측 성능이 포함되지 않는다.

Fold 4의 적합 OOF에서는 427건 중 289건이 정답이고 정상 220장 중 63장에 제안이 있었다. Fold 2에서는 388건 중 259건이 정답이고 정상 177장 중 52장에 제안이 있었다. 두 보정 풀에서 숫자가 다르므로 외측 오경보율이나 배포 정책의 승인 기준으로 옮기지 않는다. 같은 설정의 후보가 실제 fit-only VLM 초벌에 이미 등장하면 배제될 수 있다. 4개 내측 그룹의 크기도 같지 않다. Fold 4의 OOF 묶음은 229·160·160·160장, Fold 2는 204·143·142·142장이다.

Fold 4 첫 헤드는 순수 학습 50.39초로, 환경 로드와 SVD를 포함한 최초 작업 전체는 약 3분이었다. 저장한 첫 헤드를 읽어 나머지 11개를 학습하고 두 점수 배열을 생성한 구간은 147.38초였다. 이어서 Fold 2의 12개 학습과 점수 작성은 107.30초였다. 재개 프로세스에서 확인한 최대 작업 집합은 821,048 KiB였다. 이 수치는 Windows에서 표본 시점에 조회한 값이다.
