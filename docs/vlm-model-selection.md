# K-water 시각 모델 선정과 도입 실험

## CLIP을 먼저 사용한 이유

첫 단계에서는 12GB GPU에서 4B 생성 모델을 계속 다시 띄우지 않고도 이미지 누수 검사, 분류기, 임계값과 검색을 반복 비교할 수 있어야 했다. CLIP ViT-B/32는 양자화된 영상 모델이 약 89MB이고, CPU에서 사진마다 512차원 특징을 한 번 저장하면 나머지 비교는 수치 연산으로 재현할 수 있었다. 그래서 측정 기준으로 채택했다. 한계도 뚜렷하다. 224픽셀 입력에서 32픽셀 패치는 7×7개뿐이고 학습 사진의 희귀 위험은 범용 사물 분류와 다르다. 대회에 실제 제출한 시스템은 공식 Qwen3-VL-4B와 LoRA다. CLIP은 별도의 로컬 분류기와 사례 검색 실험에 사용했다. [CLIP 원 논문](https://arxiv.org/abs/2103.00020) · [원 모델 카드](https://huggingface.co/openai/clip-vit-base-patch32) · [첫 제출 기록](../results/public_submission_001.json)

## SigLIP 2 결과를 보기 전에 고정한 비교

- **주 비교**는 기존 CLIP ViT-B/32와 SigLIP 2 Base/16이다. 양쪽 모두 224×224 전체 화면 여백 입력, CPU ONNX 양자화 영상 모델, 고정 인코더와 같은 BCE 선형 분류기(L2 0.01, 250회 반복)를 사용한다. 양쪽 전용 평균·표준편차를 적용한다. 가운데를 잘라내거나 관심 영역을 선택하지 않는다. 사전학습, 패치 크기, 특징 차원과 변환 파일이 함께 바뀌므로 실제 교체 효과를 측정한다.
- **검증**은 기존 노출 170장과 6개 접두사 묶음이다. 동일·근접 중복을 제외하고 안쪽 묶음에서만 F1 최대 임계값을 고른다. 고정 0.5, 안쪽 오경보 20% 제한, 같은 8장 이웃과의 1:1 결합도 보고한다. 기준 CLIP이 기존 집계를 재현하는지 확인한다. 위험 사진에서 정답 코드 0개, 무위험 오경보, 빈 예측, 코드별 TP·FP·FN과 묶음 재표집 95% 구간을 함께 제시한다.
- **속도**는 같은 CPU·스레드·이미지·배치 1로 두 모델을 번갈아 따로 측정한다. 준비용 입력은 시간에서 제외하고 실측 표본 수와 중앙값을 공개한다. 양자화 세부 방식과 제출 서버의 GPU 시간이 다를 수 있다.
- **판정**은 새 인코더를 도입할 근거가 있는지다. 동일 모델·소스·분할을 검증한 후, 새 사건 개발 자료에서 재현할 후보를 정한다. 세 희귀 유형은 이번 170장에 양성이 없다. [SigLIP 2 논문](https://arxiv.org/abs/2502.14786) · [Google 모델 카드](https://huggingface.co/google/siglip2-base-patch16-224) · [사용한 ONNX 변환본](https://huggingface.co/onnx-community/siglip2-base-patch16-224-ONNX)

## 동일한 170장의 실제 결과

| 임계값과 판독기 | CLIP F1 | SigLIP 2 F1 | 무위험 오경보 / 66 (CLIP → SigLIP 2) | 정답 위험 0개 / 104 (CLIP → SigLIP 2) |
|---|---:|---:|---:|---:|
| 기본 분류기 · 내측 F1 보정 | 0.223 | 0.209 | 31 → 30 | 47 → 53 |
| 기본 분류기 · 임계값 0.5 | 0.195 | 0.191 | 13 → 22 | 58 → 62 |
| 기본 분류기 · 내측 오경보 20% 제한 | 0.189 | 0.099 | 9 → 8 | 62 → 84 |
| 이웃 검색 결합 · 내측 F1 보정 | 0.244 | 0.228 | 37 → 43 | 37 → 33 |
| 이웃 검색 결합 · 내측 오경보 20% 제한 | 0.197 | 0.145 | 10 → 7 | 61 → 73 |

주 비교의 SigLIP 2−CLIP 차이는 **−0.0135**였고 여섯 접두사 묶음을 2,000회 재표집한 범위는 **−0.0783~+0.0806**이었다. 걸림 정답 56건 중 CLIP은 41건, SigLIP 2는 34건을 맞혔다. 추락은 34건 중 12건과 10건이었다. 반면 기타 위험을 맞힌 수는 20건에서 23건으로 늘었다. 검색을 결합하면 정답 위험을 하나도 찾지 못한 사진은 4장 줄고, 무위험 오경보는 6장 늘었다. 같은 CPU에서 한 장 준비 실행 후 12장을 순서를 교대해 측정한 중앙값은 CLIP 42.7ms, SigLIP 2 116.4ms였다. 디스크 읽기와 모델 적재는 제외했다. [모든 코드·임계값·재표집·시간 측정값](../results/encoder_pilot.json)

**현재 결정.** 224픽셀 Base/16을 그대로 바꾸는 안은 채택을 보류한다. 두 인코더가 다르게 맞힌 위험은 전체 사진을 다시 확인하는 후보 실험에 쓴다. 이 결과는 고정 인코더와 작은 탐색 분류기에서 얻었다. 새 사건의 결과, 한국어 텍스트와의 정렬, 고해상도 입력, 지도 미세조정의 효과는 각각 별개다.

두 이웃 결합기가 함께 제안한 141건 중 69건, CLIP만 제안한 88건 중 20건, SigLIP 2만 제안한 106건 중 23건이 실제 위험 코드와 일치했다. 둘의 합집합이 제출 상한 3개를 넘는 사진은 12/170장이었다. 같은 후보 문구에 사진만 바꾼 대조를 넣어 생성기가 사진의 근거로 후보를 채택하는지 확인한다. [6개 묶음의 후보 교집합·차집합](../results/prompt_pilot_design.json)

**해상도 후속 실험의 고정 조건.** 224픽셀 결과를 확인한 뒤 동일 계열 Base/16의 384픽셀 체크포인트를 선정했다. 170장, 전체 사진 여백, 같은 내부 보정·분류기·검색·CPU 측정을 유지한다. 224와 384는 각 해상도에 맞춰 배포한 가중치도 다르므로 운영 체크포인트의 교체 효과를 측정한다. 주 비교는 내부 F1 보정 분류기다. 고정 0.5 및 오경보 제한, 위험 사진의 정답 코드 누락과 CPU 중앙 지연도 함께 기록한다. 실행 명령은 `python -m kwater_lab.encoder_pilot --prepare --resolution 384`이다. [Google 384픽셀 모델 카드](https://huggingface.co/google/siglip2-base-patch16-384)

## 생성 모델 비교와 채택 기준

1. **같은 조건부터 맞춘다.** 공식 Qwen3-VL-4B+LoRA는 제출 기준점으로 유지한다. 별도로 어댑터가 없는 원본 Qwen3-VL-4B, Qwen3.5-4B, 후순위 후보에 같은 11종 코드북·한국어 필드·최대 위험 3개·전체 사진을 제공한다. 각 모델의 공식 채팅 템플릿을 사용하고, 추론 토큰 상한과 시각 입력 예산·인코딩 방식·양자화 여부를 기록한다. 모델 교체와 지도 미세조정 효과를 분리한다. [Qwen3-VL-4B 원본](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct)
2. **코드·문장·실행을 따로 잰다.** 11종을 보존하는 변환을 사용해 위험별 TP·FP·FN, 무위험 오경보, 한 건도 맞히지 못한 위험 사진을 센다. 같은 위험을 맞힌 사례에서는 한국어 근거가 사진에 보이는지, 예방조치가 상황에 맞는지, 인용이 그 조치를 지지하는지 모델명을 가린 채 비교한다. 무효 JSON, 미관측 대체, 메모리 최대값, 처음부터 끝까지의 시간도 기록한다.
3. **결합은 단일 모델을 이길 때만 채택한다.** SigLIP 2가 새 사건에서 보완 위험을 찾아내면 생성기에 후보를 한번 제시하고, 시각적 근거가 있는 경우에만 코드로 내보내는 구성을 시험한다. 원본 VLM 단독, 같은 VLM에 후보를 주지 않고 한 번 더 확인, SigLIP 2의 후보를 주는 세 조건을 비교한다. 분류기와 생성기의 두 점수를 단순히 더하거나 최고 점수만 보고 조합을 고르지 않는다.
4. **제출은 현장 비용까지 본다.** 새 사건 개발셋에서 Macro F1 +0.02, 무위험 오경보율 증가 +3%p 이내, 중대한 위험 미탐 비증가를 우선 기준으로 삼는다. 작은 유형은 양성 사건 수를 따로 표시한다. 형식 검사, 실제 L4 런타임과 패키지 상한을 통과한 후보만 공식 공개 기준선과 비교한다.
