# K-water 성능 개선 연구 설계

2026년 11월 25일 기준. 첫 Public 제출은 공식 기준선 그대로다. 이 문서는 K-water 자료와 독립적인 1차 연구에 근거해 다음 후보를 고르는 절차를 정리한다. 개인 이미지 크로핑 연구나 Crew-Cam의 코드·모델·데이터·판정 규칙·결과는 사용하지 않는다. [제출 기록](../results/public_submission_001.json)

## 어떤 성능을 높일 것인가

1. **선발 지표**는 위험 코드별 Macro F1이다. 코드별 TP·FP·FN 및 양성 사진 수를 반드시 병기한다. 로컬 채점기는 정답 또는 예측이 있는 코드를 평균한다. 세 희귀 코드에 정답이 있는 평가셋에서 그 코드를 한 번도 반환하지 못하면 각 코드의 F1은 0이다. 가령 평가에 11종이 모두 등장하고 나머지 8종을 완벽히 맞히는 가정에서도 8종 출력 경로의 분류 점수 상한은 약 50.9/70점이다. 실제 Public의 코드 구성은 공개되지 않았다. [대회 평가](https://hackathon.imaginationgroup.co.kr/kwater/#evaluation)
2. **현장 지표**는 위험 미관측 사진의 오경보율, 위험 사진에서 아무 위험도 반환하지 못한 비율, 중대 위험별 미탐이다. 각 분모가 다르다. 위험도가 높은 오답을 분류 F1 하나에 숨기지 않도록 중대성 구간도 따로 보고한다.
3. **설명 지표**는 근거의 사진 지지, 조치 적절성, 인용의 실제 지지, 위험도 필드 유효성이다. 로컬 법령 ID 정확 일치, 사람의 익명 비교, 운영진 LLM 심사는 서로 다른 측정값이다.
4. **운영 지표**는 빈 출력 및 파싱 대체 건수, 참조 가능한 ID, 최대 GPU 메모리, 설치·기동 포함 전체 시간이다. 기본값으로 하루 2회를 소진하지 않는다. 직전 Public 후보와 비교할 단일한 연구 질문이 있는 ZIP을 선택한다.

## 근거와 전이 한계

| [Li 등, POPE](https://arxiv.org/abs/2305.10355) | 그럴듯하지만 영상에 없는 대상을 질의하면 언어모델의 시각적 환각을 드러낼 수 있다. | ‘케이블이 보임’과 ‘감전을 뒷받침하는 상태가 보임’을 구별하는 짝을 구성한다. 객체 존재를 맞히는 것만으로 사고 유형을 맞혔다고 점수화하지 않는다. |

| [Angelopoulos 등, Learn Then Test](https://arxiv.org/abs/2110.01052) | 사전 고정한 후보와 별도 보정 자료가 있을 때 예측 위험을 통계적으로 검정하는 절차를 제시한다. | 같은 170장에서 규칙을 고르고 반복 측정한 결과로 현장 오경보 보장을 선언할 수 없다. 새 사고 단위 보정 표본이 작으면 관측 수와 불확실성을 함께 제시한다. |

## 진행할 실험과 선택 기준

### E1 · 세 희귀 유형이 끝까지 보존되는지 먼저 확인

학습 입력의 대회 코드 → 지도학습 대상 → 모델 원출력 검증 → 대회 JSON 경로를 따라간다. 구형 8종 매핑에서 빠지는 유형은 데이터와 모델 양쪽에서 표현한다. 새 경로의 단위 시험에는 11종 각각, 무위험, 복수 위험 3개, 필수 근거·조치·위험성 수준을 넣는다. 구조 시험은 인공 행으로 할 수 있다. 실제 인식 능력은 사진으로 별도 측정한다.

새 후보는 동일 기반 모델에서 8종과 11종 훈련을 같은 사건 분할·같은 전처리로 비교한다. 코드마다 검증 가능한 양성 사건 수를 공개한다. 양성 한 건을 학습에 사용했다면 그 사진으로 해당 유형의 독립 재현율을 주장하지 않는다. 현 탐색셋에서 밀폐공간 양성은 0건인데 170장 중 72장에 고정 CLIP의 상위 3개 후보로 등장했다. 희귀 코드 후보를 일괄 추가하면 오경보가 크게 늘 수 있다. [희귀 후보 실측](../results/rare_candidate_pilot.json)

### E2 · 단서가 충분한 경보만 남기는 분류

기본 BCE 손실 → 비대칭 손실 → 시각적으로 유사한 음성 사례 추가 순서로 하나씩 비교한다. 동일 특징·학습 횟수·분할을 사용한다. 위험 코드, 관측 상태, 조치할 수 있는 근거를 구분해 오류를 표기한다. 먼저 걸림·추락처럼 표본이 있는 코드에서 효과를 측정하고, 양성이 부족한 코드는 수치와 한계를 분리한다.

**손실함수 소규모 비교의 고정 조건.** 이미 노출된 170장, 동일한 6개 접두사 묶음, 표준화 CLIP 특징, 정규화 0.01을 사용한다. 양성 항은 모두 BCE로 고정한다. 음성 항은 ① BCE, ② 확률에서 0.05를 뺀 뒤 0에서 자르는 조건, ③ 여기에 음성 지수 4를 적용한 비대칭 손실을 비교한다. 세 조건 모두 같은 초기값과 보수적인 보폭(기존의 1/4), 500회 반복을 사용한다. 주 비교는 ①과 ③의 내측 F1 보정 결과다. 고정 0.5와 내측 오경보 20% 제한도 병기한다. 결과를 확인하기 전에 이 세 조건을 정했으며 추가 지수나 마진을 탐색하지 않는다. 이 비교로 희귀 양성이 없는 유형의 재현율을 판단할 수 없다. [비대칭 손실 원 논문](https://arxiv.org/abs/2009.14119)

손실 실험에서 내측 F1 보정 기준 BCE는 0.2229, 쉬운 음성만 제외하면 0.2401, ASL도 0.2401이었다. 무위험 오경보는 31→45→53장이었다. ASL과 BCE의 차이 +0.0172에 대한 묶음 재표집 구간은 −0.0422~+0.0458이었다. 반대로 내측 오경보를 20%로 제한하면 ASL은 여섯 곳 중 다섯 곳에서 전부 보류를 택해 F1이 0.0486으로 떨어졌다. 별도 개발셋에서 더 세밀하게 보정할 때까지 이 ASL 설정은 제출 후보에서 제외한다. [손실별 코드·오경보·누락](../results/loss_pilot.json)

분류기·시각 이웃 각각이 맞거나 틀린 네 경우를 기록한다. 두 모델의 점수만 평균한 조건과, 추가 위험에 관측 가능한 근거가 있을 때만 채택하는 조건을 비교한다. 사진에 실제 보이는 근거를 묻는 검증과 근거 문구만 재진술하는 검증은 품질이 다르므로 판단 근거를 사람이 가린 채 평가한다. 다음 개발 목표는 위험을 하나도 맞히지 못한 사진의 감소를 유지하며 결합 모델이 추가한 오경보 6장을 줄이는 것이다. 두 모델 모두 내측 오경보를 20%로 제한한 후속 비교에서 결합은 F1 0.1890→0.1975, 오경보 9→10장, 위험이 있지만 정답을 전혀 맞히지 못한 사진 62→61장이었다. [쌍 비교 및 오류 비용](../results/weight_pilot.json)

### E3 · 가중치 공간에서 원인과 효과를 분리

1. **읽기.** 36층과 7개 선형 투영별 LoRA 업데이트의 특이값을 구했다. 큰 본체 행렬을 만들지 않고 A 전치와 B를 QR 분해해 작은 행렬에 SVD를 적용했다. 상위 8개 방향이 보존하는 총 에너지는 92.0%다. 이 값만으로 중요한 사고 유형을 알아낼 수는 없다. [공식 어댑터 분석](../results/adapter_spectrum.json)
2. **가역적 수정.** 선형 헤드의 두 코드 방향 편집은 반증됐다. 별도로 Qwen 잔차 배율 1.00과 0.75를 같은 18장·같은 시드에서 비교한다. 원본 파일은 유지하고 메모리의 배율을 복원한다. 이 실험에서 더 약한 잔차가 좋은지 확인할 수 있지만 독립 일반화를 주장할 수 없다. [탐색 프로토콜](weight-pilot-protocol.md)
3. **후속 인과 검증.** 새로 학습한 LoRA에서 동일한 실패가 다른 사건에서도 반복되고 출력 토큰 또는 층별 잔차에 일관된 차이가 보일 때, 그때 특정 층·모듈 편집을 연다. 원본, 전체 배율 조정, 표적 편집, 같은 Frobenius 크기의 무작위 편집, 원복 등 5조건을 고정한다. 해시·편집 파라미터 수·생성 예산을 기록한다. 위험 코드 이득, 근거 품질, JSON 파싱, 두 위험의 동시 검출을 비교한다.
4. **랭크 실험.** 랭크 16 원본과 8 절단을 같은 사건에서 비교한다. 작은 특이값을 제거한 손실과 동일한 규모의 대조 섭동을 별도 측정한다. 학습 시 저랭크로 훈련한 모델과 사후 절단도 구별한다. 자료 크기가 줄더라도 Qwen 본체가 차지하는 계산량은 크므로 전체 L4 시간까지 재측정한다.

### E4 · 출처가 붙어도 위험 판단이 틀릴 수 있는 경우

코드별 최빈 조문, 법령 본문 검색, 학습 사건만 사용하는 사례 검색을 고정 대조군으로 둔다. 정답 문구를 준 조건과 모델 생성 문구를 준 조건의 성능차를 측정한다. 추출한 사례를 그대로 제출문으로 복사하지 않고 생성 근거가 어떤 단어·관측과 연결되는지 점검한다. 근거가 약하면 인용을 보류하는 조건도 포함한다. 상위 1개 일치, 인용한 항목 중 실제로 조치를 지지하는 비율, 출처를 제시한 비율을 함께 기록한다. [사례 검색 실험](../results/law_examples_pilot.json)

### E5 · 부분 확대는 독립 관측 후에만 시험

기존 중앙 크롭과 전체화면 여백 비교는 CLIP의 **표준 224픽셀 입력 전처리**가 공개 사진 한 장의 위험 순위를 어떻게 바꾸는지 본 실험이었다. 관심 영역을 골라 재판독하는 기능의 효과는 측정하지 않았다. 공개 예시에서는 모델이 개구부를 묘사하고도 추락으로 연결하지 못했다. 이 경우 작은 대상의 시인성만을 원인으로 돌릴 수 없다.

우선 전체 사진 기준선의 미탐을 ‘단서를 읽지 못함’, ‘단서를 읽었으나 위험과 연결하지 못함’, ‘사진만으로 판별 불가’로 독립 검토한다. 첫 범주가 서로 다른 확인된 K-water 사고에서 반복되어야 부분 확대 가설을 연다. 착수하면 동일 사례에서 전체 사진 1회, 전체 사진 재질의 2회, 전체 사진과 제한된 부분 영상 2회를 비교해 계산량 효과도 분리한다. 비용, 미탐, 추가 오경보, 방호 설비가 잘린 실패를 함께 기록한다. 근거가 부족하면 전체 사진 판독을 유지한다.

### E6 · 외부 자료, 검증 분할, 실행 장치

외부 훈련 자료는 원 제공자의 이용 조건·신고 가능성·촬영 관점·라벨 대응·중복을 먼저 검토한다. 예를 들어 FloodNet의 항공 영상에서는 넓은 침수 면적이 잘 보이지만, 현장 근로자가 물에 빠질 수 있는지와 직접 대응하지 않는다. 허가된 범위의 자료에서 ‘공식 자료만’과 ‘외부 자료 추가’를 같은 학습 예산으로 비교한다. 추가 자료로 인한 성능 이득과 저하는 코드별로 따로 기록한다. 운영 패키지는 인터넷을 사용할 수 없다. [FloodNet 제공자](https://github.com/BinaLab/FloodNet-Supervised_v1.0) · [대회 이용 조건](https://hackathon.imaginationgroup.co.kr/kwater/#core-data)

AI-Hub 계정에서 건설 현장 위험 상태(71407), 부산 침수(71793), 고소작업(507)의 대회 참가 목적 자동승인을 확인했다. 국내 G: 저장과 출처 표시 조건으로 다루며 Git에는 출처·크기·해시를 기록한다. 건설 자료의 정상·비정상 시나리오는 원 촬영 영상 단위로 분리하고, 부산 자료에서는 실제 CCTV와 수치모델 지도를 구분한다. 고소작업은 장구류의 존재와 실제 추락 노출을 구별한다. 이번 공식 제출에는 이 자료가 포함되지 않았다. [건설 현장](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71407) · [부산 침수](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=71793) · [고소작업](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=507)

- **탐색 → 개발 후보**는 반복된 효과, 새로 줄인 미탐, 추가한 오경보의 수가 설명되는 조건으로 한정한다. 같은 개발 묶음의 여러 시험 중 최대값은 별도로 표시한다.
- **개발 → 제출 후보**는 확인된 사건 기준 개발셋에서 Macro F1 +0.02 이상, 무위험 오경보 +3%p 이내, 중대한 위험 완전 미탐 비증가를 제안 기준으로 사용한다. 지표별 해당 사진 수를 함께 보고 표본이 작으면 판단을 보류한다. 동봉 LoRA를 사용한 학습 내 진단은 이 판정의 근거에서 제외한다.
- **운영 제출** 전에는 원본과 후보에 같은 입력과 검사기를 사용하고 설치·기동·후처리를 포함한 시간을 측정한다. 실패 코드와 결과 공개 시각은 제출별로 기록한다. 다음날 공개되는 첫 Public 결과를 이후 공식 비교의 출발점으로 삼는다.
