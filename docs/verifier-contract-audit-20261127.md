# 재판독 학습 계약과 최종 수용 경로 점검

평가와 제출 실행 파일에서 같은 재판독 파서를 사용하도록 교정했다. 재판독 후보를 추가하려면 완결된 단일 JSON 객체의 명시적 수락, 후보와 동일한 코드, 유효한 정수 등급, 비어 있지 않은 근거·조치가 모두 필요하다. 기존 장면이 무위험에서 위험으로 바뀔 때는 승인된 근거로 장면 요약도 갱신한다. 이 점검의 결과는 동작 회귀이며, 생성 모델의 수락 정밀도와 Fold 0 성능은 실제 생성에서 따로 측정한다. ## 레거시 학습과 현재 추론의 대응

- 레거시 Python 3.12 보존본 SHA-256은 `699428d56d427a5c0a5fee2782bdf0497983c9c2b2fa1ffe6d170c7928a0382b`다. 동일 3.12에서 헤더 확인 후 marshal로 코드 객체를 읽고 dis로 비교했으며, 레거시 모듈이나 학습 함수를 실행하지 않았다. `verify_user_text`와 `forward_and_weighted_assistant_loss`의 바이트코드와 상수는 현재 구현과 같다.
- 양성은 `{"decision":"accept","hazard":{…}}`, 음성은 `{"decision":"reject","reason":"…"}`이다. 재판독은 학습 및 두 추론 경로에서 같은 시스템 메시지와 같은 이미지·코드별 사용자 문구를 쓴다. 시스템 메시지는 기본 장면 검사 형식을, 재판독 사용자 메시지는 후보 수락·거절 형식을 지시한다. 기존 체크포인트와 프롬프트를 일치시키기 위해 문구를 유지하고, 두 형식이 혼재된 응답은 보류한다. 현재 시스템 프롬프트 SHA-256은 `107142013bc95376c9044fc5025079f1e68dd56b4d95b20b1550deeafe4712fb`다. 학습 요약에 프롬프트 해시가 기록됐으면 평가와 패키징 모두 일치 여부를 검사한다.
- 레거시는 양성 최대 35건과 음성 최대 35건을 뽑는다. 안전 장면 음성의 우선순위가 2, 위험 장면 내 부재 코드 음성이 1이며, 내림차순 정렬 후 35건을 자른다. Fold 0 학습에는 안전 사진이 225장이라 레거시 선택 규칙상 음성 35건이 안전 장면에서 채워진다. 현재 소스는 hard negative 18건과 안전 음성 17건을 먼저 채운다. 이 구성은 레거시 체크포인트가 위험 장면의 잘못된 후보를 18건 학습했다는 증거로 쓸 수 없다.
- 레거시와 현재의 결정 정규식은 status·decision·code·가능성·중대성 스팬에 4.5배를 주고 나머지 답변 토큰은 1배로 처리한다. 현재 인코더는 채팅 접두사와 답변의 개별 토큰화가 전체 시퀀스와 정확히 맞는지도 검사한다. 로컬 Qwen processor와 224×224 합성 이미지에서 두 메시지의 접두사 1,640토큰을 모두 마스킹했다. 수락은 감독 48토큰 중 20개가 4.5배, 거절은 14개 중 5개가 4.5배였다. 가중 causal CE의 assistant-tail 계산은 CPU 합성 로짓에서 전체 시퀀스 참조식과 일치했다.

## 수용과 장면 합성

| 응답 또는 상태 | 현재 동작 |
|---|---|
| 정확한 수락 JSON, 후보 코드 일치, “발판 단부에 보호 난간이 없다” | 후보 수락. 보호장치 부재는 위험 근거로 유지 |
| 명시 거절 또는 다른 코드로 수락 | 후보 보류. 초안은 유지 |
| 검사 형식·수락 형식 혼재, 무위험 status 또는 거절 reason 필드 추가 | 후보 보류 |
| “추락 위험이 확인되지 않는다” 또는 “추락 위험이 보이지 않는다”라고 적힌 수락 근거 | 후보 보류 |
| 잘린 JSON, 중복 키, 배열·코드 펜스·앞뒤 설명, surrogate 문자, 자리표시자, 잘못된 등급 | 후보 보류 |
| 무위험 초안에 유효 후보를 하나 추가 | 수락된 근거를 장면 요약으로 사용하고 위험 상태로 변환 |

이전 재판독 호출점은 초안용 느슨한 파서를 사용해 앞뒤 설명이나 배열 안의 수락 JSON을 잘라 받아들일 수 있었다. 일반 장면 초안에는 기존 복구 방식을 유지하고 재판독 응답은 완결 JSON으로 한정했다. 명시적 부정 점검은 표의 표현처럼 제한된 패턴에서 동작한다. 사진과 문구의 정합성, 열린 표현의 부정·추측과 비교는 실제 눈가림 검증의 범위다. [공유 파서 회귀](../tests/test_verifier_contract.py)

공식 Qwen 원생성의 보호 패널 제외 개발 39장을 별도로 재생했다. 기존 위험 항목 중 현재 코드와 그대로 일치한 25건의 원문 근거와 조치를 고정 수락 객체로 감싸 25건 모두 형식 검사를 통과했다. 형식 변환 결과에서는 32/32건이 통과했다. 공식 개발 정답의 추락 설명 중 보호조치 부재를 언급하는 원문 14건도 모두 수용됐으며 그중 13건이 난간을 언급했다. 원생성 무위험 요약 12건과 개발 무위험 근거 290건에는 이번 정규식의 명시적 위험 부정 표현이 없어, 그 부정 경계는 아래의 독립 회귀 예제로 재현했다. 원문 확인은 포매터 이전 증거 텍스트의 재생이며 VLM이 실제로 반환한 재판독 응답은 아니다.
## 후보 게이트와 Fold 0 독립성

Fold 0은 전체 개발 보정값과 인샘플 정밀도를 사용하지 않는다. 기존 Fold 0 외측 체크포인트만 사용하며 파일 SHA-256은 기존 집계와 일치했다. temperature 1, 코드·장면 기준 0.50을 고정하고, 기존 위험이 있으면 미출력 코드 점수 0.54 이상을 요구한다. 기존 위험이 없으면 코드 0.62 이상과 장면 0.58 이상을 함께 요구한다. 제안은 최대 두 개이고 기존 코드를 지우지 않으며 총 세 슬롯을 넘지 않는다. 레이블을 보는 절차가 게이트에 없으므로, 위험 성능을 보고 이 한도들을 재선택하지 않는 한 이전 교차-외측 보정의 간접 누수 경로가 열리지 않는다.

실제 생산 패키지에서 활성화되는 전문 분류기는 전체 개발 폴드 앙상블·전 개발 보정·개발 OOF 정밀도의 별도 설정이다. 패키저는 이 구성을 Fold 0 전용 어댑터와 함께 묶는 것을 거부한다. 그 정밀도는 개발에서 적합한 보정에 기반하므로 새 사진의 검증기 수락 정밀도는 별도 측정해야 한다. 이번 확인에는 79장 재사용 패널 채점과 새 학습을 포함하지 않았다.
