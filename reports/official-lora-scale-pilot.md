# 공식 LoRA의 배율을 낮췄을 때 18장 판정 변화

2026년 11월 26일, 공식 Qwen3-VL 기반 모델과 배포 LoRA를 한 번 적재해 같은 사진 18장을 두 번 판독했다. 기본 배율 1.00에서 0.75로 낮추자 위험 집합이 8장에서 바뀌었다. 정답 집합과 정확하게 일치한 사진은 9장에서 6장으로 줄었다. 새로 완전 일치한 사진은 0장이었고, 이전 일치를 잃은 사진은 3장이었다. [실측 집계](../results/adapter_scale_pilot.json)

## 실행 조건

노출된 탐색 사진 170장에서 6개 접두사별로 해시 순서 첫 3장을 선택했다. 정답은 선발에 사용하지 않았다. 두 조건은 사진 순서, 공식 모델·프롬프트·생성 함수, 배치 1, 시드 42, BF16, SDPA, 900토큰 출력 한도를 공유한다. 활성 LoRA 층 252개의 기존 배율에 조건값을 곱해 사용하고 각 조건이 끝나면 원래 값을 복원했다. [재현 명령](../docs/paired-vlm-pilots.md)

RTX 3060에서 원래 체크포인트 읽기 경로를 시도했을 때 Windows 네이티브 프로세스가 첫 shard에서 접근 위반으로 종료됐다. 완주한 실행에서는 safetensors 0.8이 `pread`로 CPU에 가중치를 읽고 Transformers가 텐서를 원래의 CUDA 장치에 올렸다. 공식 코드 파일과 모델 가중치는 변경하지 않았다. 체크포인트 2개 적재는 199초, 로더 호출과 관련 라이브러리 준비를 합친 시간은 3,243.9초였다.

생성 호출 시작부터 해당 조건의 행을 반환받기까지 기본 배율은 1,205.3초, 낮은 배율은 332.4초였다. 기본 배율을 항상 먼저 실행했고 첫 장에 751.5초가 걸렸다. 같은 모델을 재사용한 후속 조건과의 시간 차이는 배율에 따른 추론 속도 개선으로 해석할 수 없다.

Windows 프로세스 시작 시각은 01시 11분 59초, 두 조건의 채점 집계 파일을 처음 저장한 시각은 03시 04분 43초였다. 시작부터 집계 기록까지 1시간 52분 44초가 걸렸다. 이 시간에 후속 CPU 형식 검사는 포함되지 않는다.

## 평가 범위

저장한 원생성을 주최 측 포매터에 다시 넣었다. 배포 법령 목록을 사용했고 검색용 학습 예시는 비웠다. 변환한 두 제출 파일 모두 공식 `check_output.py` 검사에서 18행을 인정했고, 변환 전후의 위험 코드 집합도 각각 18장 모두 일치했다. 제출 파일과 검사기 해시는 [형식 재생 집계](../results/adapter_scale_pilot.json)에 있다.

배포 LoRA는 대회 학습 자료를 사용했고, 18장은 탐색 과정에 이미 노출된 표본이다. 사진 ID 접두사와 독립 사건의 일치 여부는 확인되지 않았다. 이 표의 차이는 해당 18장에서 관측한 현상이다. 관측 근거·조치에 대한 사람 판정과 새로운 사건에 대한 성능 검증은 별도로 남는다.
