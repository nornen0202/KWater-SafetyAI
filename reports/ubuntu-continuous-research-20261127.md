## 공간 위험 후보 순위

공식 기반 모델의 동일한 4×4 특징에서 전체 평균과 상위 세 영역 평균을 각각 학습했다. 각 폴드에서 다른 두 폴드로 160스텝 학습한 뒤 검증 사진당 하나의 위험 후보를 내었다. 전체 개발 사진은 575장, 실제 위험이 있는 사진은 399장이다.

| 입력 화소 상한 | 전체 평균 적중 | 상위 세 영역 적중 | 폴드 1·2·3의 적중 차이 |
|---|---:|---:|---|
| 262,144 | 262/399 | 271/399 | +5, +5, −1 |
| 393,216 | 264/399 | 271/399 | +7, +4, −4 |

영역 세 곳을 보는 모델은 각 해상도에서 순적중이 늘었지만 Fold 3에서는 줄었다. 정상 사진에서도 강제로 한 개를 고르는 평가이므로 승인 뒤의 정상 오경보율은 미측정이다. 같은 예산에서는 262,144화소를 우선하며, 동일 사진의 회복·손실과 사건 그룹 재표집 구간을 후속 감사에서 계산한다. [폴드별 집계](../results/ubuntu-continuous-spatial-20261127.json)

**16시 47분 GPU 쌍체 검산.** 262,144화소에서 두 모델이 모두 맞힌 사진은 235장, 모두 놓친 사진은 101장이었다. 영역 모델은 전역 모델의 미탐 36장을 회복하고 기존 적중 27장을 잃었다. 차이는 +2.26%p, 117개 사건 그룹을 폴드별로 2,000회 재표집한 95% 구간은 −1.02~+5.25%p였다. 학습 라벨 벡터만 섞으면 적중은 전역 137건·영역 120건으로 줄었다. 동일 특징에 CPU로 재학습했을 때는 262건·263건으로 영역의 이득이 작아졌다. GPU의 재실행은 262건·271건을 재현했다. 따라서 CPU 재학습과 GPU 재학습을 같은 가중치의 재채점으로 취급하지 않는다. 후속 검증에서는 제안 정책만으로 성능 개선을 단정하지 않고 회수한 36장과 잃은 27장의 비대칭을 검증한다.

## 새 기반 모델 대조군

로컬 3050에서 배포 어댑터 없이 Qwen 기반 모델에 멀티모달 QLoRA를 학습한다. 개발 Fold 1·2의 374장으로 만든 500개 학습 예시만 사용한다. 131,072화소, gradient accumulation 8, 시드 20261127, 초기 12 optimizer steps로 고정하고 6스텝마다 체크포인트를 저장한다. 훈련 목록의 SHA-256은 `9897bff9009b78f95f2c58fe50c30c4a18775887dbdd6854c6c012c905d436ac`이다. 12스텝은 비교를 위한 초기 예산이다. 실전 평가는 새로운 어려운 음성 선택 방식을 같은 학습 예산으로 비교한 후에 진행한다. 두 팔의 셔플·이미지·출력 형식과 평가 호출 수를 맞추고, Fold 3 결과를 보고 학습 예시를 다시 고르지 않는다.

재개할 때 `data/ubuntu3050-runs/qlora-inner12-base-control/`의 체크포인트·학습 원장을 먼저 확인한다. 실행 서비스는 `kwater-qlora-inner12-control`이다. `kwater-research-spatial-resolution`은 위 두 해상도 실험 전용이었다. 단일 GPU 잠금을 공유한다. 원본 체크포인트와 사진별 예측은 이 PC에 보관하고 Windows에는 비식별 집계와 재현 조건을 전달한다.

### 대조군과 실험군의 차이

훈련 Fold 1의 사진에는 Fold 2로만 학습한 헤드를, Fold 2에는 Fold 1로만 학습한 헤드를 썼다. 해당 사진에서 정답에 없는 코드 중 모델이 가장 높게 예측한 후보를 검증기 기각 예시로 만들었다. 대조군의 어려운 음성 18자리 중 13자리에서 코드가 바뀌었다. 시드와 실제 학습 순서를 적용하면 첫 12스텝의 96개 예시 중 차이는 **2개**, 첫 차이는 2스텝에 나온다. 적은 감독 신호에 대한 짝지은 시험이다. [실험군 학습 코드](../kwater_lab/ubuntu_mined_verifier.py)

평가 전에 Fold 3 전체 201장과 걸림·추락·낙하 또는 인양의 세 후보를 고정했다. 두 12스텝 체크포인트를 같은 사진·프롬프트·화소·NF4에서 평가하고, 승인과 기각의 로짓 차이가 0보다 큰 경우만 승인한다. 양쪽 예측을 저장한 뒤 TP·FP·FN, 정상 오경보와 중대성 4 누락을 대조한다. 이 결과는 주어진 위험 후보의 승인 성능이다.

**학습 상태.** 대조군 12스텝과 checkpoint-12 저장을 확인했다. 이어 실험군이 같은 단일 GPU에서 언어·시각 계층의 기울기 사전 검사를 통과했다. 채택 판단은 두 체크포인트의 실측 평가 후에 내린다.

**자동 인계.** 실험군 서비스 `kwater-qlora-mined-queued`가 GPU를 반환하면 `kwater-inner12-paired-eval`이 같은 잠금을 획득한다. 이 서비스는 검증한 평가 소스의 지문과 체크포인트를 확인하고 양쪽 603개씩 총 1,206개 승인 마진을 수집한다. 개별 예측을 검증해 봉인한 뒤 비공개 `data/ubuntu3050-runs/inner12-paired-verifier-aggregate.json`에 집계를 쓴다. 운영 회차에서 검산한 수치만 Git에 전달한다. [평가 실행기](../kwater_lab/ubuntu_inner_verifier_eval.py)

### 17시 12분 후속 실험 사전 설계

두 팔의 학습은 모두 12스텝에서 종료됐다. Fold 3 쌍체 평가가 첫 팔의 예측을 저장하는 동안 아래 조건을 정했다. 이 시점에는 두 팔의 채점 결과를 열지 않았다.

1. **사진이 판정에 기여하는가.** 같은 코드 질문에서는 입력 사진만 바뀐다. 양쪽 예측이 봉인되면 CPU에서 동일한 코드의 마진을 다른 사건 그룹 사진과 일대일로 교환한다. 양 팔에 시드 20261127의 동일한 256개 순열을 적용한다. 각 코드의 승인 건수는 정확히 보존된다. 올바른 사진에 연결했을 때 코드별 AUROC와 세 코드 평균이 얼마나 높은지, 기존 0 임계값에서 F1·정상 사진 오경보·중대 미탐이 얼마나 달라지는지 측정한다. 순열의 범위는 사진과 정답의 연결을 끊은 대조 분포다. 그룹 독립성이나 일반화 신뢰구간을 추정하는 용도로 쓰지 않는다.
2. **학습량을 고정할 때 직접 승인·기각을 가르치는 편이 나은가.** 기존 혼합 대조군과 같은 기반 모델·LoRA 초기화·화소·96회 사진 제시·12회 옵티마이저 갱신을 사용한다. Fold 1·2의 걸림, 추락, 낙하·인양 각각에 양성 16개, 정상 음성 8개, 다른 위험 음성 8개를 배정한다. 학습 분할의 코드별 양성은 117장·85장·27장이며 각각 24·18·8개 그룹에 분포한다. 정상 사진은 108장이다. 평가와 같은 JSON 접두사 뒤 첫 결정 토큰에만 손실을 준다. 이 비교는 표본 구성과 학습 목표를 함께 바꾸므로 개별 요소의 효과는 추가 실험에서 분리한다.
3. **판정과 이관.** 새 팔도 기존과 같은 Fold 3의 201장, 세 코드, 고정 임계값으로 평가한다. 하한이 0을 넘는 사건 그룹 쌍체 95% 구간과 ΔMacro-F1 ≥0.03, 전체 정상 사진 오경보율 ≤20%, 중대 위험 완전 미탐 증가 없음을 모두 만족해야 Windows 전체 생성 경로 검증 후보로 전달한다. 세 위험의 승인 점수로 공식 11코드 성능이나 리더보드 상승폭을 추정하지 않는다.

**실행 조건.** 직접 감독 학습에 들어갈 96장의 입력 인코딩을 CPU에서 확인했다. 57개 그룹에 걸쳐 Fold 1에서 49장, Fold 2에서 47장을 골랐으며 같은 사진을 두 번 사용하지 않는다. 학습 순서 지문은 `03dccef2f9baa022a5793fa1221ab1d42d098e45e92f5817afeaea6966a3363f`이다. 승인과 기각은 각각 토큰 10330과 46996이다. 두 팔의 첫 12회에 적용되는 학습률을 맞추기 위해 대조군의 63스텝 코사인 일정과 4스텝 워밍업을 그대로 사용한다. 새 팔은 시작 시 어려운 음성 팔과 초기 가중치 지문을 대조한다. 원래 혼합 대조군은 초기 지문을 기록하지 않아 초기화 설정으로 비교한다. 혼합 대조군에만 버려지는 첫 역전파가 있어 드롭아웃 난수 경로는 달라질 수 있다.

**재현과 복구.** 로컬 환경에서 `.venv/bin/python -m kwater_lab.ubuntu_focused_verifier prep`으로 목록과 인코딩을 검사한다. 같은 모듈의 `train`은 새로운 학습을 시작하고, `resume`은 완료된 0·6·12스텝 체크포인트에서 원장과 옵티마이저·난수 상태를 복구한다. 서비스 `kwater-focused12-train`은 기존 쌍체 평가와 하나의 GPU 잠금을 공유한다. 독립 CPU 서비스 `kwater-inner12-image-alignment`는 봉인 후 256개 사진 교환 대조를 계산한다. Fold 3의 가장 큰 그룹 하나가 201장 중 94장이므로, 후속 직접 감독 비교에서는 원래 201장 주평가와 함께 그 그룹을 제외한 107장의 민감도도 보고한다.

서비스 `kwater-focused12-eval`은 직접 감독 모델의 12번째 체크포인트가 저장되면 아래 명령을 실행한다. 원래 평가와 지문이 같은 대조군 마진 603건을 재사용하므로 추가 GPU 추론은 새 모델의 603건이다. 두 모델의 인코딩 입력 지문이 모든 사진·코드에서 일치해야 채점한다. 검산한 집계만 전용 브랜치에 이관한다.

```bash
.venv/bin/python -m kwater_lab.ubuntu_focused_eval run \
  --source data/ubuntu3050-runs/inner12-paired-eval/ca732b396a6c86cae4fc7f82 \
  --focused data/ubuntu3050-runs/qlora-inner12-focused-verifier/training/checkpoint-12 \
  --report data/ubuntu3050-runs/focused12-mixed-comparison-aggregate.json
```

**17시 27분 Windows 인계.** 메인 브랜치의 `cd7561b`까지 통합했다. Windows의 Fold 4 v3 학습은 8/154스텝 이후 종료됐고, 완료한 8코드 대조군의 생성이 17시 14분 시작됐다. 드라이버 이벤트와 종료 사이의 인과관계는 미확인이다. 다섯 번째 제출은 보류 상태다. Ubuntu는 예정된 Fold 1·2 학습과 Fold 3 고정 비교를 이어간다. 메인 PC의 48장 수동 영역 비교에 필요한 비공개 키와 판독 원장은 여전히 미수신이며, 17시 14분 Drive 조회는 할당량 오류(HTTP 403)였다. ### 17시 31분 결과 · 사진별 순위와 실제 승인 사이의 간격

고정한 Fold 3 사진 201장에는 세 후보에 해당하는 정답이 111건 있었다. 두 모델의 마진 1,206개를 모두 봉인한 뒤 아래 수치를 계산했다. 개별 예측에서 TP·FP·FN을 다시 세고, 별도의 AUROC 구현으로 코드별 값을 검산했다.

| 12스텝 모델 | TP / FP / FN | 세 코드 Macro-F1 | 정상 사진 오경보 | 중대성 4 정답 코드 누락 | 사진과 정답을 맞춘 Macro-AUROC | 다른 그룹 사진으로 교환한 평균 AUROC |
|---|---|---:|---:|---:|---:|---:|
| 혼합 학습 대조군 | 2 / 0 / 109 | 0.0242 | 0/68 | 30/30 | 0.7385 | 0.4952 |
| 어려운 음성 교체 | 0 / 0 / 111 | 0.0000 | 0/68 | 30/30 | 0.7571 | 0.4959 |

어려운 음성을 넣은 모델은 603개 후보를 모두 기각했다. 대조군에서 맞혔던 걸림 두 건도 잃었다. 실제로 학습한 96개 예시 중 교체된 예시는 두 개여서 더 많은 음성 교체의 효과는 이번 비교로 알 수 없다. 양쪽 모두 중대성 4를 전부 놓쳐 현재 승인 규칙을 이관할 근거가 없다. 한편 걸림·추락·낙하 또는 인양 순서의 AUROC는 대조군 0.845·0.815·0.555, 교체군 0.842·0.824·0.605였다. 사진을 교환한 256회에서 세 코드 평균 AUROC의 최댓값은 각각 0.571·0.565였다. 현장 배경과 그룹 차이를 포함한 시각 신호가 순위에 남아 있다. 무엇이 실제 위험의 근거였는지는 이 대조로 특정할 수 없다. [쌍체 판정 집계](../results/ubuntu-inner12-paired-verifier-20261127.json) · [사진 교환 대조](../results/ubuntu-inner12-image-alignment-20261127.json)
