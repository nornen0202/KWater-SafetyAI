# 공식 4B 원본에 v2 재판독을 붙이는 대응 검증

기존 216장 비교에서 v2 단독은 공식 1차 LoRA보다 활성 코드 Macro-F1이 0.1075 낮았다. 다음 분기는 공식 원본의 판정과 기존 위험 항목을 유지하고, Fold0 외측 OOF 전문가가 빈 슬롯에 제안한 위험 한 종류만 v2로 다시 확인한다. 최초 후보 목록을 만들 때 공식 원생성·공식 포맷 216장과 OOF 점수만 사용했다. 기존 Fold0 재판독 코드의 고정 0.5 기준, 기존 위험이 있을 때의 +0.04 여유, 빈 판독의 +0.12 및 장면 점수 0.58 기준을 유지했다. 정답과 확정 제외 마스크의 성능은 후보 목록을 디스크에 고정한 뒤 계산했다. [기존 대응 결과](../results/fold0_qlora_v2_118_bf16_paired.json) · [후보 상한 집계](../results/v2_official_anchored_oracle.json)

| --- | ---: | ---: |
| 제안 수 | 102 | 18 |
| 정답에 있는 제안 / 주석에 없는 제안 | 31 / 71 | 5 / 13 |

| 공식 기준 / 정답만 추가의 중대성 4 완전 미탐 | 20 → 11 / 49 | 5 → 2 / 13 |

CPU 후보 고정과 정답 대조를 처음 완료하는 데 26.05초가 걸렸고, 같은 목록을 다시 검증한 호출은 10.44초였다. 위 수치는 실제 재판독 수용률이나 개선 성능이 아니다. 정상 오경보가 늘어났고 F1도 낮아진 무검증 추가는 사용하지 않는다. 잔여 34장도 후보 채택을 단독으로 결정하는 표본이 아니다.

기존 FT 기준 하이브리드와 zero-shot GPU 작업이 끝난 뒤 같은 GPU 큐를 사용한다. 사진 바이트, 위험 코드, 프롬프트·VLM 소스, 어댑터·정밀도, 프로세서 크기, 배치 1 및 320토큰 상한이 모두 일치하는 이전 원문만 재사용한다. 나머지는 실제 재판독을 생성하고 배치별 캐시를 남긴다. 공식 위험의 기존 코드·근거·조치·등급·인용 객체는 읽기 전용으로 보존한다. 새 법령 검색은 새로 승인한 위험에만 적용한다. 무위험 판정에 새 위험이 승인된 경우만 상태를 바꾸고, 공식 스키마가 허용하지 않는 무위험 장면 설명 필드를 새 출력에서 제거한다. 그 장면 설명은 원래 출력에 남는다. 전체 216장 검사 이후에만 증분 TP·FP, 오경보, 중대성 미탐, 실제 추가 시간과 34장 민감도를 기록한다. [실행기](../kwater_lab/official_anchored_verifier.py)

사전 연산량 확인에서 같은 저장 OOF 점수를 v2 원 포맷에도 적용하면 90개가 제안되고, 공식 원본 기준의 102개와 사진·코드 65개가 겹쳤다. 원문 캐시의 설정·사진 해시까지 일치한다면 약 37회 새 생성으로 줄일 수 있다. 이전 검증의 실제 재사용 수와 신규 생성 시간은 이 추정에서 제외했다.

```powershell
python -m kwater_lab.official_anchored_verifier --freeze-only --out results/v2_official_anchored_oracle.json
```

실제 생성은 기존 GPU 실행을 마친 후 같은 Python 환경으로 `--verify --out results/v2_official_anchored_verified.json`을 실행한다. 원문, 개별 승인 판단 및 최종 행은 `data/` 아래의 로컬 경로에 저장한다.

## 실제 BF16 재판독

102개 제안 중 65개는 지문이 일치한 기존 원문을 재사용했고, 나머지 37개를 새로 생성했다. 77개가 수용됐고 공식 출력 검사는 216/216이었다. 추가 생성과 모델 로드는 809.0초, 전체 호출은 942.9초였다. 전체 Macro-F1은 0.60308→0.60528로 0.00220 올랐으나 사건 단위 95% 구간이 −0.07123~+0.04672였고, 무위험 오경보가 6→17/65장으로 증가했다. 34장 민감도는 0.64649→0.62052로 하락했다. 이 조건은 승격하지 않았다. ## 공식 무위험 출력을 보존한 사후 재생

216장 성능을 본 뒤, 공식 출력에 이미 위험이 1~2건인 사진에서만 같은 승인 결과를 남기는 조건을 한 번 확인했다. 77개 승인 중 53개를 남겼고 공식 무위험 행 86개는 원래 JSONL 바이트 그대로 보존했다. 공식 검사기는 216/216을 통과했다. 현재 CPU 재생은 15.94초, 추가 호출 0회였다. 이 216장에 처음 적용한다면 재판독 전에 남는 제안 63개를 호출하게 된다. 이는 기존 102개보다 39회 적다.

## 원 제안 사진에서의 2순위 오라클

원 동결 파일의 SHA-256과 102개 1순위의 ID·이미지·행 위치·코드 순서를 확인했다. 같은 전문가 점수와 기존 적격 기준에서 2순위까지만 꺼냈다. 첫 후보가 실제 정답이면 유지하고, 틀린 경우에만 두 번째 정답을 추가했다. 사진당 실제 추가는 최대 1건이다. 기존에 위험을 2건 출력한 사진에서도 빈 슬롯 하나에 대한 두 대안을 비교했다. GPU 호출이나 실제 재판독은 없었다. [2순위 집계](../results/v2_official_anchored_rank2_oracle.json)

| 지표 | 전체 216장 | 제외 후 34장 |
| --- | ---: | ---: |
| 1순위 회복 → 2순위까지의 오라클 회복 | 31→36 / 78 | 5→6 / 16 |
| 1순위 잔여 FN 중 원 제안 사진 안 / 밖 | 27 / 20 | 8 / 3 |

| 2순위 오라클 Macro-F1 | 0.70834 | 0.75231 |
| 중대성 4 완전 미탐 공식 → 1순위 → 2순위 | 20→11→9 / 49 | 5→2→2 / 13 |

전체에서 새로 회복한 5건은 전도 2건과 추락·기타·화학 노출 각 1건이다. 1순위가 제안한 사진 밖에 남은 20건은 이 방법의 범위를 벗어난다. 이 수치는 추가 비용과 후보 순위의 범위를 보여 주는 사후 오라클이다. 접수 성능이나 실제 추가 호출 감소를 입증하지 않는다.
