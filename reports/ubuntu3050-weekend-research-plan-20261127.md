## 2. 점수 개선 실험의 순서와 판정

**A. 사진 한 장당 한 제안으로 공간 후보를 학습한다.** 같은 고정 Qwen3-VL 기반 시각 인코더에서 4×4 영역 특징을 저장한다. 전역 평균 선형 헤드와, 같은 수의 가중치로 코드별 상위 3영역을 평균하는 다중 인스턴스 헤드(MIL)를 비교한다. 첫 비교는 시드·화소·업데이트·후보 수를 같게 한다. 새 지역화 모델로 절대 위치나 촬영 배경만 외울 수 있으므로 출처 및 그룹별 기여를 함께 본다. 작은 물체의 가시 단서가 반복해서 누락된다는 가설은 시각 검색 연구에서 가져왔고 국내 현장 사진에서 직접 시험한다. [V* 시각 검색](https://arxiv.org/abs/2312.14135) · [다중 인스턴스 학습 원 논문](https://proceedings.mlr.press/v80/ilse18a.html)

1. 공식 이미지 1,045장의 고정 특징은 라벨 없이 계산할 수 있다. 학습·정규화 통계·임계값 선택은 해시가 일치한 개발 manifest에서만 허용한다. Fold 1·2·3을 차례로 하나씩 검증으로 보류하고 나머지 두 폴드의 그룹으로 학습한다. 검증 정답을 열기 전 코드 후보 순서를 고정한다. Fold 0, Fold 4와 과거 79장 보류는 튜닝에서 제외한다. 이미 파악한 동일 장면 그룹이 경계를 넘는지 검사하고, 의심 그룹 제외·출처 하나 제외 결과를 별도로 남긴다. 공식 분할은 실제 현장 ID의 추정치다. [정본 분할과 해시](../results/clean_split_v1_summary.json)
2. 첫 지표는 동일 후보예산의 recall@1(위험 사진당 올바른 코드 제안), 코드별 AP와 평가 가능한 코드 수다. 초벌 출력 도착 후 **누락된 사진·코드 중 후보에 들어온 수 / 초벌이 놓친 총수**로 실제 보완 효과를 측정한다. 기존 후보와 새 후보의 교집합·새 TP·새 FP·추가 처리시간을 함께 기록한다. 사전 연구 진척 기준은 3개 폴드 중 2개 이상에서 개선되고 합친 누락 회수율이 5%p 이상 상승하는 것이다. 고정 예산으로 이 기준에 못 미치면 두 번째 후보를 모든 사진으로 확대하지 않는다.
3. 위치에 근거한 효과를 검증한다. 선택 영역과 같은 크기의 다른 영역을 같은 사진에서 미리 결정하고 전체 화면을 두 조건에 모두 제공한다. 선택 영역·대조 영역·전체 단독에 같은 모델·코드·생성 예산을 쓴다. 같은 사진의 선택/대조 영역에서 이득이 비슷하면 확대나 추가 토큰 자체가 원인일 수 있다. 4×4 토큰 순서만 섞으면 top-k 평균이 그대로이므로 그 연산을 위치 효과 검정으로 쓰지 않는다. [시각 대조 디코딩의 대조 조건](https://arxiv.org/abs/2311.16922)

**B. 검증기는 훈련 중 실제로 헷갈린 위험을 학습한다.** 검증 사진 밖의 그룹에서, 해당 사진을 보지 않고 예측한 후보를 먼저 고정한다. 같은 코드·비슷한 장면에서 참 양성과 오승인을 짝짓는다. 예를 들어 젖어 보이는 바닥과 실제 미끄럼 단서, 장비 존재와 인양 중인 하중을 구별한다. 주석 누락이 의심되는 음성은 별도 큐에 격리한다. 양성/음성 수, 무위험 사진 수, 희귀 코드와 출처 분포를 공개한다. 우연히 잘 나온 한 코드의 정책을 다른 폴드에 소급하지 않는다.

동일 원 기반 모델·NF4·batch 1로 두 조건을 재생한다. 첫 조건은 일반 참/거짓 후보, 둘째는 난이도와 코드가 맞춰진 후보를 쓰며 양·음성 수와 업데이트 수를 동일하게 한다. 3050에서는 순전파·역전파·저장·재로드가 되는 8스텝으로 시작한다. 제안 초깃값은 LoRA rank 8, 학습률 1e−4, 누적 8, 1에폭 상한이며 T=0·고정 화소로 평가한다. 메모리가 부족하면 시각부 동결·어댑터 위치와 화소를 기록해 **양쪽을 같은 조건으로 처음부터** 비교한다. 가용 시간은 첫 8스텝의 중앙값·최댓값과 검증/저장 실측으로 다시 잡는다. 매 25 optimizer step 또는 에폭 경계에서 어댑터, optimizer·scheduler·난수 및 그룹 목록 해시를 함께 저장한다. [QLoRA 원 논문](https://arxiv.org/abs/2305.14314)

고정 81후보 P3은 위 새 학습 실험의 선행 진단이다. 기존 v2로 동일 후보·가중치·프롬프트·화소·정밀도에서 전문가 점수, 기존 생성 승인, JSON 결정 접두사의 한 토큰 마진을 대조한다. 정답 28/81로 AP 비교 기준은 약 0.346이다. 75개 공통과 미판독 6개를 구분한다. 기존 임계점과 같은 재현율의 정밀도, AP, 정상 사진 오경보를 본다. 81개에서 임계값을 찾으면 탐색으로 표시한다. 3050의 NF4와 Windows BF16을 직접 빼서 학습 효과로 해석하지 않는다. [기존 후보 원장](../results/v2_official_anchored_true_nested_replay.json)

**C. 같은 위험 코드에서 근거·조치·조문을 바꿔 정성 배점을 검증한다.** A/B 양쪽에 같은 사진, 같은 위험 코드와 등급을 준다. A는 현재 문장 생성·검색, B는 ① 가시 대상·상태·관계를 한정해 기록 ② 관찰된 상태에 맞는 조치 우선순위를 생성 ③ 제공 법령에서 그 행위와 대상을 직접 지지하는 조문을 연결한다. 불명확한 상태는 단정하지 않는다. 첫 조문 ID 적중, 조치 직접 지지, 사진 근거 타당성, 잘못된 조치 건수를 따로 센다. 잘못된 조문이 비슷한 단어를 포함한 경우와 대상만 바뀐 조문을 음성 대조로 둔다. 인용 품질을 별도 평가하는 설계 근거가 있다. [ALCE 인용 평가](https://arxiv.org/abs/2305.14627) · [현행 조치·조문 검산](../results/prevention_law_guard_eval.json)

**채택 기준.** A·B의 조합은 공통으로 정의한 코드별 TP/FP/FN, 매크로 F1, 중대 위험 완전 미탐, 모든 정상 사진 오경보, 처리시간으로 결정한다. 개발 단계의 Windows 후보 이관 기준은 그룹 쌍체 ΔMacro-F1 ≥+0.03, 95% 구간 하단 >0, 정상 사진 오경보 ≤20%, 중대 완전 미탐 증가 없음이다. 그룹을 복원추출해 같은 표본으로 두 조건을 다시 채점한다(새 연구에서 2,000회, 시드 20261127). 드문 코드별 양성 사진·그룹 수와 양성 0인 재표집을 명시한다. 기존 채점기 결과는 원 설정을 보존한다. 구간이 넓으면 효과·불확실성·추가로 필요한 그룹을 보고하고 제출 후보 승격은 보류한다. 개선된 후보 회수율만으로 통과할 수 없다.

## 4. 주말 운용과 협업

모든 시각은 KST다. 반복 연구는 Codex 로컬 앱의 이 대화에 예약했다. 금요일 20시부터 매시간 다음 실험을 점검한다. 집계 푸시는 00·04·08·12·16·20시, 중요 실험 종료 시점과 일요일 23시에 한다. 주 에이전트가 분석·설계·평가·지휘·운용을 맡고 구현·테스트 작성은 GPT‑6.2 Sol에 배정한다. 일요일 23시는 집계 전용이며 23:59에 종료한다. 긴 GPU 실행은 독립적인 systemd 사용자 서비스 하나가 맡고, 다음 회차는 그동안 CPU 분석·입력 검수·커밋을 진행한다. GPU 점유율과 함께 **완료한 새 비교 수, 재사용한 특징 수, 후보당 비용**을 기록한다. 정보가 더 생기지 않는 반복 학습으로 GPU를 채우지 않는다.

**첫 실험.** 금요일 20시에는 Codex 회차와 별도로 한 번 실행할 GPU 작업을 둔다. 정본 수신에 성공하면 3개 폴드(177·197·201장)의 두 위험 후보 헤드를 학습한다. 정본이 늦으면 키트 6장 학습·4장 보류의 같은 위치 과제를 393,216화소로 실행해 262,144화소 결과·시간과 대조한다. 키트 원본의 개별 ID와 분할은 로컬에 남긴다. 긴 계산을 시작한 서비스는 원격 연결과 분리돼 있고 해당 PC에서 실행된다. [첫 실험 기동기](../tools/ubuntu_weekend_first.sh) · [GPU 작업 관리](../tools/ubuntu_weekend_gpu.sh)

**수신 계약.** Git에는 코드/설정/보고서/비식별 집계와 지문을 둔다. Windows에서 가장 먼저 필요한 작은 파일은 `data/clean-split-v1/split_manifest_dev.json`(SHA-256 `3864848fe26b951ec070710499d2694078b17c76ffd2aaf38d312b99ad3b2f60`)이다. Windows에서 기존 비공개 인계 폴더 내 `ubuntu-weekend-20261127/split_manifest_dev.json`으로 먼저 전달할 수 있다. Ubuntu의 `tools/ubuntu_weekend_split.sh`는 이 소량 인계를 검증하고, 전량 복원이 먼저 끝난 경우 별도 복원 경로의 정본을 찾아 채택한다. 이어서 로컬 그룹 제외 목록, P0의 39개 캐시, 원 v2 어댑터·프롬프트·정렬한 81개 후보, 세 예측, 최종 ZIP 순으로 받는다. 제한 자료의 이동은 기존 인계 문서가 허용한 비공개 복원 경로로 한정한다. 개별 사진·ID·생성문·가중치는 Git에 넣지 않는다. 전량 Drive 복원은 `READY.json`과 manifest 해시가 맞을 때 별도의 빈 경로로 재개한다. 제한·권한 오류에는 파일별 재시도 간격을 늘리고 로컬 연구를 계속한다. [복원 계약](../docs/ubuntu-3050-handoff.md) · [데이터 사용 규칙](../AGENTS.md)

**작업 중 버전.** 입력·모델 파일·프롬프트·코드·정밀도·화소·시드·폴드·소비시간과 마지막 완료 단위를 실행별로 보관한다. Windows v3 실행 소스 지문은 `455facb4…30ee`다. 공유 브랜치 파일이나 같은 파일명의 최신 소스를 자동으로 동등하게 취급하지 않는다. Windows는 main, Ubuntu 연구 결과는 `ubuntu/weekend-20261127`에 일반 푸시한다. 회차 시작 시 fetch, GPU 작업이 끝난 경계에서만 통합한다. 이름을 명시한 자체 소스·보고서·집계만 stage하고 diff 검사·관련 테스트 후 `tools/ubuntu_weekend_publish.sh '요약' reports/ubuntu-….md`처럼 검토한 경로만 전달해 푸시한다. 충돌이면 로컬 커밋 보존, fetch 후 변경을 검토한다. 강제 푸시와 빈 커밋은 쓰지 않는다. 소규모 브랜치 통합은 Windows가 완료한 연구를 그대로 보존한다.

**원본이 늦어질 때.** 공식 학습셋 이미지는 고정 모델의 특징만 한 번 추출하고, 정본이 도착할 때까지 라벨 기반 적합을 미룬다. 그동안 키트 10장의 서로 겹치지 않는 사진으로 고정 특징에서 타일 위치를 학습하는 양성 대조와 위치 라벨을 섞은 음성 대조를 수행한다. 위치가 구분돼도 해당 특징이 위험을 검출한다는 뜻은 아니다. 다음은 동일 키트의 실제 기본 판독/선택적 2차 호출 비용과 저장·재개를 비교한다. 위험 코드가 고정된 생성문이 도착하기 전에도 제공 법령만으로 제목→본문 검색을 학습한다. 동일 제목·본문을 제거하고 조 단위 보류에서 무학습 문자 검색, 저랭크 학습 및 학습 쌍 셔플을 대조한다. 본문에 제목·조 번호가 남으면 정답이 노출되므로 제거한다. 이 검사는 법령 내 검색을 판별하고, 실제 예방 행동을 조문이 지지하는지는 C의 눈가림 평가로 판단한다. 정본 없이 임의 분할을 만든 F1, 키트로 학습한 가중치, 외측 폴드에 노출된 임계값은 승격하지 않는다.

**장애와 복구.** 실행 전 마운트 UUID, 디스크 20 GiB 여유, CUDA와 온도·가용 VRAM, 중복 작업을 확인한다. 기동기는 프로젝트 디스크, GPU용 단일 유닛과 파일 잠금, 마감까지 남은 시간, 자식 전체 종료를 적용한다. CPU 로깅과 임시 결과는 로컬 `data/`·`.runtime/`에 둔다. OOM이면 다른 세션을 종료하지 않고 자기 프로세스만 정리해 batch 1·낮은 화소로 최대 1회 새 조건을 시도한다. 비정상 온도, 반복 OOM, 해시 불일치, 디스크 부족이면 해당 실험을 멈추고 마지막 정상 체크포인트를 보존한다. 통신 장애 시 15분·1시간·다음 회차로 늦추고 계산은 로컬에서 계속한다. 푸시 실패 후에는 원격 SHA를 먼저 확인한다. 오래 걸리는 새 모듈은 테스트와 기동기 허용 목록 추가 후 가동한다. [systemd 타이머 동작](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)

```bash
tools/ubuntu_weekend_gpu.sh check
systemctl --user status kwater-weekend-gpu.service
journalctl --user -u kwater-weekend-gpu.service -n 30
git ls-remote origin refs/heads/ubuntu/weekend-20261127
```

긴급 중지 시 로컬 `.runtime/WEEKEND_STOP` 파일을 만든 뒤 `tools/ubuntu_weekend_gpu.sh stop`으로 실행 중 유닛을 종료한다. Codex 예약을 일시정지하고 `kwater-weekend-awake.timer`와 `kwater-weekend-awake.service` 중 활성 항목을 중지하면 절전 억제도 해제된다. 호스트의 AC 자동 절전은 해제 상태이며 금 20시부터 일 23:59까지 별도의 일회성 절전 억제도 예약했다. 사용자 서비스는 로그인 세션에서 확인했다. 정전 뒤 자동 로그인·프로젝트 디스크 재마운트·Codex 재기동·Git 재인증까지의 무인 복구는 검증하지 못했다. PC 전원과 로그인 상태를 유지하고 화면은 잠글 수 있다.

실행 환경은 Ubuntu 사용자 서비스 안에서 CUDA 텐서 계산과 Git 원격 조회를 통과했다. 전용 브랜치 푸시는 격리한 Git 원격에서 변경·무변경·제한 경로·중지 표식을 대조했다. 첫 GPU 작업은 분할 도착/지연, 잠금 충돌, 일부 결과, 완료 영수증 변조, 마감 후 기동 거부를 점검했다. `kwater-weekend-first.timer`와 `kwater-weekend-awake.timer` 모두 금요일 20시 대기 상태를 확인했다. 실제 주말 예약 실행과 그 결과는 각 회차가 남기는 커밋으로 판정한다.

프로젝트 루트에서 아래 명령으로 재현한다. 첫 줄은 무라벨 캐시 검산이다. 두 번째 묶음은 정본이 수신된 뒤 주말 기동기를 통해 위험 후보 헤드를 학습한다. 법령 실험 원문과 개별 판정은 각 PC의 `data/`에 저장된다.

```bash
.venv/bin/python -m kwater_lab.spatial_probe --precompute-images data/train/images --device cuda --max-pixels 262144
tools/ubuntu_weekend_split.sh &&
  tools/ubuntu_weekend_gpu.sh run kwater_lab.spatial_probe --manifest data/clean-split-v1/split_manifest_dev.json \
    --device cuda --seed 20261127 --steps 160 --top-k 3 --report data/ubuntu3050-runs/spatial-development.json
.venv/bin/python -m kwater_lab.ubuntu_law_control --device cpu --out data/ubuntu-law-control/report.json
```

P3 실제 입력은 수신 영수증의 후보 JSON SHA를 `--expected-proposal-sha256`, 원 v2 가중치 SHA를 `--expected-adapter-sha256`에 지정한다. 진단용 공식 어댑터 결과와 섞이지 않도록 원 어댑터·프롬프트를 검사한다. 현 시점 로컬에는 원 v2와 순서 고정 81개 파일, Windows 세 출력과 ZIP이 없다. Drive 조회에서 공유 클라이언트의 분당 요청 한도(403)가 관측됐다. 관련 테스트 11건은 통과했다. 전체 112건 중 109건 통과·1건 건너뜀·2건 입력 누락 오류였다. 오류 두 건은 개발·보류 정본을 직접 여는 기존 테스트로, 해당 파일 수신 후 재실행한다.
