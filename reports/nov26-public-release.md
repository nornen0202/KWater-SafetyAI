실제 main.py는 모델의 8종 코드로 법령 조문과 배포 사례집을 함께 검색하고 첫 조문을 붙인 뒤 제출 코드로 변환한다. 과거의 18장 형식 검사에는 빈 사례집이 사용됐다. 이번 비교에서는 실제 배포 법령과 사례집을 모두 사용해 기준 출력을 재현했다.

1차는 해당 위험의 생성 근거와 예방조치 양쪽을 읽어 일부 인용의 적용 요건을 확인한다. 해체 현장의 작업반경 통제에는 주최 측이 동봉한 제384조, 위에서 떨어질 물체와 하부 출입 통제에는 제14조를 적용한다. 연결 근거가 없는 개구부 방호·낙하물·구축물 안전성 평가 인용은 철회한다. 대체 조문은 동봉 자료에서 활성 상태인 조 단위 항목이어야 한다. 사진별 위험 코드, 등급, 근거, 예방조치, 미관측 장면 문장이 모두 동일한지 비교했다.

## 2차 후보의 위험 코드

2차는 모델이 이미 출력한 위험 항목의 이름을 근거·예방조치와 맞춘다. 구조재의 변형과 안정화 조치, 사면의 손상과 보강 조치가 함께 기술된 경우 구축물 불안정에 해당하는 공식 `other`를 복구한다. 상부 부재와 낙하 방지·하부 통제가 함께 나타난 경우 낙하물로 해석한다. 바닥이나 통로의 걸림, 개구부, 건축물 전체의 안정성 등 다른 원인이 관찰되면 해당 조건에서 재분류를 제한한다. 이전 위험 수, 문장, 위험성 등급은 보존한다. 변경한 코드에 맞는 인용은 기존 공식 검색기가 고른다.

주최 측 8종 모델에서 `collision_contact`는 표준화 과정에서 `other`가 되고 `struck_crushed`는 `struck_by_lifting`이 된다. 개발 920장의 공식 8종 주석 772개에서 동일 근거·예방문을 대조한 결과, 원본 변환표는 모두 공식 분류와 일치했다. 이번 수정 대상은 모델이 생성문에서 내린 위험 유형 선택이다. 드문 3개 코드를 자동으로 채우지 않는다.

이득이 나온 3장은 이미 탐색한 두 사진군에 속한다. 규칙 설계에도 이 출력을 참고했다. 18장 정량 환산 차이는 +8.61/70점이며 공식 Public 점수 추정치로 사용할 수 없다. 개발 920장의 정답 문장으로 같은 판단 조건을 점검했을 때 772개 위험 중 30개에서 기전이 식별됐고 29개가 정답 코드와 일치했다. 1개는 낙하물과 비계 불안정이 혼재했다. 배율 0.75로 저장된 동일 18장에서는 두 후보 모두 변경이 0장이었다. 실제 사진의 원출력 문구에 따라 적용 범위가 달라진다.

이전에 보존한 텍스트 사례 분류기의 18장 점수에는 원래 위험과 다른 후보가 두 건 있었다. 두 제안 모두 같은 사진에 이미 있는 걸림 코드였다. 한 건은 실제로 잘못된 낙하물 항목이었고 다른 한 건은 정답인 기타 위험이었다. 중복 코드를 허용하지 않는 원래 경로에서는 두 제안 모두 적용되지 않았다. 이 분류기와 B2는 모두 같은 생성문의 표현을 읽으므로 두 판정의 일치를 별도 사진 증거로 볼 수 없다.

17:30:14 KST에 고정한 C는 기존 항목 두 개가 한국어 관찰과 예방조치 양쪽에서 충분히 겹칠 때 중복 한 건을 제거한다. 사례 검색의 두 문장 순위가 두 항목에서 같은 생존 코드를 지지해야 한다. 제거할 항목의 구별되는 관찰 절이 원래 코드를 지지하면 보존한다. 사례 적합에 사용한 개발 11그룹·310개 주석에서 관찰 유사도 0.35343, 조치 유사도 0.60의 경계를 고정했다. 사진이나 위험을 추가하지 않으며 남은 항목의 근거·조치·등급·인용은 그대로다.

C는 개발 18장에서 잘못된 낙하물 한 건을 제거했다. 해당 코드에 참양성이 없어 F1은 0.524382로 같았다. 적합 그룹 밖의 17그룹에서 서로 다른 정답 위험이 함께 있는 88장·189개 항목을 모두 유지했다. 실제 단일 위험에 똑같은 문장을 가짜 코드로 복제한 합성 대조 263장에서는 가짜 코드 170개를 제거했지만 진짜 코드를 대신 제거한 사진도 2장 있었다. 이는 사람이 쓴 주석으로 확인한 동작 범위다. 64장 원생성 평가는 고정 시각 뒤에 생성된 새 사진, 기존에 판독하지 않은 그룹, 텍스트 적합에도 없는 그룹을 따로 집계한다.

## 형식과 시간

공식 키트 10장의 당시 포매터 중간 파일에서 모델 필드를 복원하고, 원래 main.py의 최종 10행과 모든 필드가 일치하는지 확인했다. 개발 18장은 배율 1의 저장된 원출력을 사용했다. 각 후보의 main.py에서 GPU 생성 함수에만 해당 출력을 주입해 공식 포매터·법령 검색·결과 쓰기·키트 검사를 실행했다. 각 후보가 키트 10/10, 개발 18/18 유효 행을 기록했다. 배포 LoRA와 사례집은 종전 채점본에 포함된 자료다. 개발 검증용 신규 자료의 범위는 920장이며 보류 125장의 사진·정답은 검사하거나 채점하지 않았다.

최초에 개발 분할 파일을 찾으면서 기존 통합 manifest의 첫 70줄을 표시해 일부 보류 항목의 식별자와 코드 메타데이터가 화면에 노출됐다. 보류 사진, 개별 정답 원문, 평가 결과를 조회하거나 성능 분석에 사용하지 않았다. 이후 신규 정답 조회는 920개 개발 ID를 먼저 대조해 통과한 행으로 제한했다. 125장의 실제 독립 평가는 별도 담당자에게 인계한다.

## 재현과 인계

작업 기준 폴더는 `G:/Projects/KWater-SafetyAI/data/submissions/nov26-evidence`다. `a-paired.json`, `b-paired.json`은 사진군별 집계이고, `a-examples.json`, `b-examples.json`은 로컬 전용 변경 전후 원문이다. `a-archive.json`, `b-archive.json`, `b2-archive.json`, `ab2-archive.json`에는 각 파일의 SHA-256, 크기, 구성원별 CRC32 및 공식 해제·명세 검사 결과가 있다. 전체 집계는 같은 폴더의 `release-index.json`에 있다. 이 폴더의 검증 해제본 네 개는 합계 36,225,062,337바이트다. 자동 정책이 임시 해제 폴더의 재귀 삭제를 차단해 G:에 보관했다.

```powershell
$data = 'G:/Projects/KWater-SafetyAI/data'
$evidence = "$data/submissions/nov26-evidence"
python tools/nov26_prepare_archive.py "$data/packages/kwater-baseline.zip" "$evidence/rebuild.staging"
python tools/nov26_finalize_archive.py "$data/packages/kwater-baseline.zip" "$evidence/rebuild.staging" "$evidence/rebuild-a.zip" --scoped
python tools/nov26_verify_archive.py "$data/packages/kwater-baseline.zip" "$evidence/rebuild-a.zip" "$data/local-kit/kit" "$evidence/rebuild-a-extracted" "$evidence/rebuild-a-receipt.json"
```

B는 새 스테이징 파일에 `--risk`, B2는 `--observed`를 지정한다. A의 인용 변경을 함께 적용할 때에는 `--scoped`를 추가하고 다른 파일명으로 저장한다. C의 고정 코드는 `--redundancy-config`에 근거 폴더의 `c-redundancy-config.json`을 전달하면 조립할 수 있다. 재빌드된 ZIP 항목의 기록 시각이 달라지면 파일 전체의 SHA-256도 달라질 수 있다. 네 가지 정책을 같은 개발 원생성에 재생하는 명령은 작업 트리에서 `python -X utf8 G:/Projects/KWater-SafetyAI/data/submissions/nov26-evidence/compare_four.py`다.
