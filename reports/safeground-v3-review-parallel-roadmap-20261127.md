4. **검증 결과와 실제 ZIP을 연결.** 동일한 소형 고정 입력에서 연구 실행과 ZIP 진입점의 코드·수용/기각·조문·형식 오류를 비교한다. 검수 시점 범용 패키저는 기존 booster와 formatter를 사용하고 있었다. v3 마진·조치 검사·프롬프트가 실제 배포 경로에 들어갔는지 확인해야 한다. 전량 모델은 79장까지 포함한 고유 학습 1,045장, 법령 사례 수, 전문가 5폴드×3시드, 전량 보정 파일 지문을 개별 대조한다. Fold 4 모델과 전량 모델을 서로 다른 후보로 기록한다. Linux 오프라인 설치부터 Public 1,800초/Private 3,600초까지 실측하고 후보당 ZIP SHA·사용한 출력·채점 영수증을 연결한다. [오프라인 검사 절차](../docs/fifth-archive-offline-audit-20261127.md)

## 4. 다른 PC에서 동시에 진행할 실험

보조 장비는 인계 문서의 Ubuntu 26.04·OEM RTX 3050을 기준으로 설계했다. 이번 검수는 Windows에서 수행했다. Ubuntu의 접속·복원 상태, 실제 VRAM과 BF16 지원은 현장에서 확인할 항목이다. 비공개 핵심 자료 전송 영수증에는 584파일·22,437,232,196바이트가 기록돼 있다. 약 600 GB 전체 복원은 별도 절차로, 서버의 `READY.json`과 manifest, 조각 해시를 확인한 뒤 시작한다. 이미 승인된 자료가 복원된 경우 아래 각 실험에 필요한 파일만 사용한다. 전체 복원 중이면 완료된 별도 작업 디렉터리에서 실험한다. Windows의 G: 분리, AI-Hub 전체 자료 또는 유료 클라우드는 이 계획의 선행 조건에 포함되지 않는다. [Ubuntu 인계와 환경 확인](../docs/ubuntu-3050-handoff.md) · [핵심 자료 전송 영수증](../results/ubuntu-3050-transfer-20261127.json)

**우선순위와 중단 기준.** P0는 즉시 시작할 수 있고 P1·P2는 본 PC의 추론 완료를 기다린다. P3는 그동안 진행 가능한 별도 연구다. 첫 20분은 드라이버·가용 메모리·batch 1 로드 확인에 배정한다. Windows에서 4B BF16 예열 시 약 11.6 GiB가 사용된 전례가 있어 3050의 메모리로 가능한지 먼저 본다. OOM 또는 지속적인 CPU 오프로딩이 생기면 동일 정밀도 속도 비교를 종료하고 P0~P2에 집중한다. 4비트 실행을 시도하면 별도 모델 조건으로만 기록한다. 12장 관측으로 81장 시간을 다시 산정하고, P4 후보가 도착하면 실험 중간 산출물을 저장한 뒤 패키지 검증을 우선한다. [Linux 파일럿 환경과 메모리 실측](../docs/linux-fold0-parallel-readiness-20261127.md)

**이미 있는 CPU 진입점.** 다음은 프로젝트 루트, Python 3.12 환경에서 쓰는 명령이다. P0에는 고정 캐시, 공식 라벨·법령 및 기준 검색기 파일이 필요하다. P1에는 세 예측 JSONL, 개발 manifest, 공식 훈련 주석, 기존 로컬 그룹 제외 목록과 그 SHA가 들어 있는 추적 집계가 필요하다. 두 작업 모두 모델 가중치 없이 수행할 수 있다. 아래 P1 명령은 8종과 각 v3의 107장 비교를 만든다. 직접 비교할 때는 같은 CLI에 `--legacy8 "$pred/v3_11code_standalone.jsonl" --v3 "$pred/v3_hybrid_margin_verified.jsonl"`을 주고 출력 파일명을 바꾼다. 그 결과의 내부 키 `legacy8`은 이 호출에서 v3 단독을 가리키므로 경로·SHA와 실제 모델명을 함께 보관한다.

```bash
mkdir -p data/ubuntu3050-runs
export CUDA_VISIBLE_DEVICES=-1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
python -m kwater_lab.production_law_replay --root "$PWD" --out data/ubuntu3050-runs/production-law-replay.json

pred=data/local-eval-predictions/fold4-v3-benchmark
python -m kwater_lab.fold4_crosssplit_audit score --score-output data/ubuntu3050-runs/8-vs-v3-107.json
python -m kwater_lab.fold4_crosssplit_audit score --v3 "$pred/v3_hybrid_margin_verified.jsonl" --score-output data/ubuntu3050-runs/8-vs-hybrid-107.json
```

P3·P4 GPU 측정은 위 CPU 환경변수를 쓰지 않는 별도 셸에서 한다. 원본·사진 ID·개별 생성문은 각 장비의 비공개 `data/`에 보존한다. Git에 합칠 결과는 입력·마스크·어댑터·프롬프트·출력의 SHA-256, 실제 실행 커밋, 수치 정밀도·화소·메모리·시간, 그룹별 집계와 채점 조건이다. [39장 기준 집계](../results/native_11code_production_law_replay.json) · [Fold 4 고정 마스크 원장](../results/fold4-crosssplit-audit.json)

**첫 결과 이후의 연구 순서.** 하이브리드가 정답 후보를 찾고도 정상 오경보를 늘리면 전문가 보정 점수만, 마진만, 두 점수 결합의 세 조건을 같은 후보에서 비교한다. 사진과 그룹을 먼저 나누고, 완전 미노출 내측 사진의 초벌 예측으로 절단값을 정한 뒤 외측을 한 번 평가한다. 보정에 쓸 수 있는 고유 그룹과 양성·음성이 부족하면 불확실성을 보고하고 새 학습에 앞서 자료를 늘린다. 반대로 제안 목록 밖에 미탐이 집중되면 후보 생성 회수율과 오라클 상한을 먼저 재산출한다. 두 조건에서 모두 같은 오류가 지속될 때만 공통 790장의 8종/11종 통제 재학습으로 넘어간다. 이때 학습 업데이트·출력 토큰 예산과 평가 조건을 맞추고, 정책 개발에 이미 사용한 Fold 0·4와 겹치지 않는 그룹을 확증용으로 먼저 확보한다.
