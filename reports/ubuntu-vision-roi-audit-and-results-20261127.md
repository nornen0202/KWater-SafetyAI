실제 윤곽은 빈 박스 대비 오답 1건을 제거했지만, 이동 윤곽과 비교하면 정답 1건을 잃고 오답 1건을 추가했다. 실제 설명은 교환 설명과 비교하면 정답 1건을 얻고 다른 정답 1건을 잃었으며 오답 1건을 제거했다. 어떤 조건에서도 정답 코드 집합과 완전히 일치한 사진은 6/12로 같았다. 이 파일럿에서 **의미가 맞는 윤곽 또는 문장 자체의 순이득**을 확인하지 못했다. 이동 윤곽을 제출 정책으로 고를 근거도 없다.

## 정본을 사용한 575장 학습

공식 기반 Qwen의 고정 4×4 시각 특징에서 전체 평균 헤드와 16개 영역 중 최고 점수 한 곳을 쓰는 헤드를 각각 GPU에서 160스텝 학습했다. 헤드별 파라미터 수와 후보 예산은 같다. 세 번의 학습에서 검증 폴드의 사건 그룹을 학습에서 제외했다. 575장은 원래 48장 선택 조건을 적용하기 전의 개발 집합이다. 모델이 반환한 위험 후보 한 개가 실제 위험 중 하나면 적중으로 센다. 정상 사진의 오경보나 전체 생성 F1은 이 지표에 포함되지 않는다. 첫 실기에서 발견한 학습 파라미터 CPU/GPU 불일치도 고쳐 주말 예약과 같은 코드 경로를 확인했다.

| 검증 폴드 | 사진 / 그룹 | 전체 평균 → 영역 최대, 정답 1순위 | 전체 평균 → 영역 최대, 공통 8코드 평균 AP |
|---|---:|---:|---:|
| 1 | 177 / 41 | 91 → 92 / 136 | 0.6036 → 0.5700 |
| 2 | 197 / 38 | 83 → 88 / 130 | 0.5941 → 0.5738 |
| 3 | 201 / 38 | 88 → 82 / 133 | 0.6730 → 0.6016 |

전체 적중은 **262/399 대 262/399**다. 단일 영역 최대값만 써서 전역 특징을 대체할 근거가 없다. 금요일 예약 회차에는 같은 데이터와 예산에서 상위 3개 영역의 평균을 쓰는 사전 계획을 유지한다. 후보 회수 개선이 재현되면 원경과 관계 영역을 함께 보는 선택적 재판독으로 연결하고, 유형별로 새로 회복한 정답과 추가한 오답을 집계한다. [공간 특징·학습 코드](../kwater_lab/spatial_probe.py)

## 다음 실험의 우선순위와 인계

1. **48장에서 재판독의 상한 확인.** Windows의 세 입력을 그대로 사용한다. 48장 전체의 미탐 회복·기존 정답 손실·신규 오경보를 먼저 산출하고, 사전에 판독한 관계 지지/반대 12장과 불명확 36장을 각각 표기한다. 24장의 잘림 사진에서 같은 배율 ROI와 모든 영역을 담은 ROI의 차이를 따로 본다. 검토자에게 영역 위치와 위험 계열이 주어진 상한이다. 확증 단계에서는 두 번째 사람이 일부 관계·부재를 눈가림 재판독한다.
2. **원인별로 하나만 바꾸기.** 48장 수동 위치가 미탐을 회복한 유형에서만 사람·통로, 작업자·단부, 하중·하부 공간의 두 역할을 모두 제안하는 개방어휘 검출기를 기존 Base와 비교한다. 사람이 실제로 가시하다고 확인한 대상만 위치 회수율 분모에 넣고, 대상 부재·너무 작은 박스·두 역할 중 하나 누락을 따로 센다. 경계가 중요한 부류에서만 진짜/가짜 윤곽을 비교한다. 캡션은 검증 가능한 관찰에 한정하고 출처·법령을 생성하지 않는다.
3. **제출 후보 결정.** 개발 폴드 내부에서만 라우터를 맞춘 뒤 후보 한 개를 고정한다. Windows의 기존 생성과 보조 PC 재판독을 같은 평가 사진·프롬프트·가중치·정밀도에서 대조한다. 정상 사진 전체, 중대성 4, 한국어 근거의 관찰 가능성·조치의 직접성까지 함께 채점한다. 이미 본 175/107장은 회귀 비교다. 서버와 같은 L4·빈 캐시에서 200장 1,800초/300장 3,600초에 설치·검출·생성·저장이 모두 들어가는지 확인한 뒤 승격한다. ### 재현

Ubuntu 프로젝트 루트에서 아래 순서로 실행한다. 각 GPU 프로세스는 같은 잠금을 사용한다. 원본 사진, 키, 모델, 생성 원문은 로컬 `data/`에 남는다. 같은 종류의 평가라 해도 Windows 48장에 쓰는 Fold 0 v2 어댑터와 이번 파일럿의 배포 어댑터를 구분한다.

```sh
.venv/bin/python tools/prepare_ubuntu_roi_pilot.py
.venv/bin/python tools/prepare_ubuntu_roi_pilot.py --model-download-commands
# 초회에는 출력된 공식 가중치 다운로드 및 해시 검증 명령을 실행한다.
.venv/bin/python -m kwater_lab.ubuntu_roi_views
run=$(flock .runtime/ubuntu-weekend-gpu.lock .venv/bin/python -m kwater_lab.ubuntu_roi_readout predict | tee /dev/stderr | sed -n -e 's/^SEALED_RUN=//p' -e 's/^sealed run already complete: //p')
.venv/bin/python -m kwater_lab.ubuntu_roi_readout score --run "$run"
.venv/bin/python -m kwater_lab.ubuntu_roi_generation prepare
.venv/bin/python -m kwater_lab.ubuntu_roi_generation predict
.venv/bin/python -m kwater_lab.ubuntu_roi_generation score
.venv/bin/python -m kwater_lab.ubuntu_roi_followup
.venv/bin/python -m kwater_lab.ubuntu_roi_generation predict --run-dir data/ubuntu-roi-20261127/generation-followup
.venv/bin/python -m kwater_lab.ubuntu_roi_generation score --run-dir data/ubuntu-roi-20261127/generation-followup
flock .runtime/ubuntu-weekend-gpu.lock .venv/bin/python -m kwater_lab.spatial_probe --device cuda --max-pixels 262144 --top-k 1 --steps 160 --seed 20261127 --manifest data/clean-split-v1/split_manifest_dev.json --report data/ubuntu3050-runs/spatial-roi-dev-top1.json
```

48장 정본 키만 전달받았을 때는 `tools/prepare_vision_roi_panel.py --from-key`로 빈 검수 자료를 재구성한다. 원 메인 PC의 검수 결과를 사용하려면 별도로 대응하는 판독 원장과 어댑터도 확보한다. 프로젝트의 원본 출력과 제출 키트 검사를 포함한 수치·해시는 [Ubuntu 집계](../results/ubuntu-vision-roi-20261127.json)에 있다.
